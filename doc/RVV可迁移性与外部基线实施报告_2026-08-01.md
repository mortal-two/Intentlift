# RVV 可迁移性与外部基线实施报告（2026-08-02 修订）

## 1. 当前口径

正式后端集合现为 **24 个 Triton 来源 J**：原 22 项加 Llama4 RoPE 与 FlashAttention forward。此前误混入的
TileLang Gather2D、RowMask Where2D 已从输入、专用 adapter、外部 baseline 与结果 aggregate 中删除。它们的
数值不得继续用于论文；按 IR 结构匹配的通用 gather/row-mask compiler pass 仍保留为后端能力。

RVV 外部实验回答三个不同问题：

1. `LLVM-RVV C`：独立 C 语义实现经 Clang/LLVM 迁移到 RVV，衡量普通编译路径；
2. `Triton-CPU/RVV`：同一 Triton Source 经上游 CPU backend 在 RVV4 真实执行，衡量直接迁移；
3. `Best Native RVV`：严格匹配时，在 Expert RVV 与 ggml CPU/RVV 中机械选择最快者，衡量目标竞争力。

内部归因始终使用同一三柱：

```text
C-Fixed       canonical lowering + C schedule，无搜索
Schedule-Only 同一 lowering，只搜索 schedule
Full          同一 J 上增加结构/数值 lowering path，再分别搜索 schedule
```

## 2. 当前覆盖

| 实现 | 覆盖 | 准确含义 |
|---|---:|---|
| LLVM-RVV C | 23/24 | FlashAttention forward 当前 N/A |
| Triton-CPU/RVV | 8/24 correctness；7/24 formal latency；1 项 quick | 真实同源迁移子集 |
| Expert RVV | 4/24 | TVD、LayerNorm、xFormers RMSNorm、Flash backward preprocess |
| ggml CPU/RVV | 5/24 adapter；4/24 formal latency；1 项 quick | 只接严格同边界 graph |
| IntentIR RVV | 23/24 可生成 | 不是 24/24 的正式三柱性能矩阵 |

因此可以声称“同一个 J 已在 GPU 与 RVV 上形成不同目标实现”的直接案例，但目前不能声称“24 个 J 的 RVV
性能矩阵已经完整”。

## 3. 当前可继续使用的正式 RVV 结果

RVV4 为 RV64GCV、VLEN=128；当前结果均为单线程、固定 affinity、code-warm/data-cold、交替配对。外部比值
`external / Full > 1` 表示 IntentIR 更快。

| Kernel | C-Fixed (µs) | Schedule-Only (µs) | Full (µs) | `G_schedule` | `G_full` | LLVM-RVV C / Full | Best Native / Full |
|---|---:|---:|---:|---:|---:|---:|---:|
| TVD | 494062.57 | 301694.86 | 46255.39 | 1.638× | 6.522× | 0.971× | 0.954× Expert |
| Softmax | 493062.53 | 311769.56 | 31646.82 | 1.581× | 9.852× | 7.599× | 1.617× ggml |
| xFormers RMSNorm | 2492980.84 | 527097.38 | 107831.15 | 4.730× | 4.888× | 1.647× | 1.109× Expert |
| Flash backward preprocess | 1913189.67 | 1286453.22 | 44713.90 | 1.487× | 28.771× | 2.490× | 1.634× Expert |
| Llama4 RoPE | 19520.92 | 19020.23 | 19020.23 | 1.026× | 1.000× | 0.614× | N/A |
| Fused Add RMSNorm | 157422.42 | 80358.77 | 37983.62 | 1.959× | 2.116× | 0.803× | N/A |
| Flash one-pass LayerNorm | 2195898.88 | 1197061.52 | 497259.87 | 1.834× | 2.407× | 0.205× | N/A |

七项内部归因几何平均：`G_schedule=1.824×`、`G_full=4.636×`。Best Native 只对前四项适用，其适用子集
几何平均仍为 `1.293×`，不能外推为全 24 项。

LLVM-RVV C 的逐项数值保留，但暂不计算七项 aggregate：最新三项使用完整 `rv64gcv_zfh_zvfh` 编译目标，旧四项
需要用同一 flags 重新配对后才适合合并。最新数据同时暴露了真实负例：Flash one-pass LayerNorm 的 Full 约为当前
LLVM-RVV C 的 `4.88×` 延迟；这应当作为 RVV f16 vector codegen 缺口，而不是从表中删除。

这七个具体案例对应真实 MLIR 路径，而不是 Python kernel emitter：

- TVD：共享输入的 multi-output sibling fusion，消除第二次完整遍历；
- Softmax：fused vector reduction/approx-exp/normalization path；
- xFormers RMSNorm：显式 scalable-vector reduction 与 epilogue；
- Flash preprocess：FP16 load、FP32 widening product 与 vector reduction；
- Llama4 RoPE：interleaved pair rotation 的 contiguous vector packet；Full 的 head-angle reuse 未胜出，是负例；
- Fused Add RMSNorm：producer-consumer fused path 消除 materialized 中间遍历；
- Flash one-pass LayerNorm：同一 fused path 把多输出 producer/reduction/epilogue 合入单一实现状态。

后两项的 J-derived roofline 点进一步说明 Full 的收益来源：

| Kernel | Arithmetic intensity | Schedule logical GB/s | Full logical GB/s | `G_full` |
|---|---:|---:|---:|---:|
| Fused Add RMSNorm | 0.312 flop/byte | 1.671 | 3.534 | 2.116× |
| Flash one-pass LayerNorm | 0.785 flop/byte | 0.196 | 0.473 | 2.407× |

这里是 certified boundary 的逻辑最小流量，不是硬件计数器 DRAM bytes；它可以解释同一边界工作量下的有效吞吐，
不能冒充实测带宽。

长 kernel 的测量器也已经改为每个 cold-data batch 目标计时 `200 ms`、至少一次、最多 16 次；候选、finalist 与
correctness 次数不变。Flash one-pass LayerNorm 同一 38-candidate bundle 的端到端实验耗时从 `3013.9 s` 降到
`306.5 s`（`9.83×`），而 Full latency 从 `496.61 ms` 变为 `497.26 ms`，差异仅 `0.13%`。这是实验吞吐改进，
不是 kernel 性能加速。

### 3.1 RVV C-prior pilot

最新三个完整 latency map 在 `B=12` 下得到：

| Kernel | Erase-C/C @ B=12 | 到 95% 最优：C / Erase-C |
|---|---:|---:|
| Llama4 RoPE | 1.000× | 1 / 1 |
| Fused Add RMSNorm | 1.000× | 3 / 2 |
| Flash one-pass LayerNorm | 1.000× | 5 / 6 |

因此当前 RVV pilot 没有 best-at-budget 收益，搜索顺序也有正有负。C-prior 的 GPU 结果不能直接外推到 RVV；后续要么
增加目标特征，要么把它如实保留为 RVV 负结果。

## 4. Triton-CPU/RVV

上游 Triton-CPU 已在 RVV4 真实生成并执行八个 accepted Source：SwiGLU、Softmax、KLDiv、Flash backward
preprocess、DYT、GeGLU、Liger RMSNorm、LayerNorm。统一 formal latency 的七项为：

| Kernel / natural shape | IntentIR Full | Triton-CPU/RVV | Triton / Full |
|---|---:|---:|---:|
| SwiGLU `[16384,11008]` f32 | 5.403 s | 10.849 s | 2.008× |
| Softmax `[2048,4096]` f32 | 31.602 ms | 368.069 ms | 11.647× |
| KLDiv `[4096,4096]` f32 | 421.789 ms | 577.482 ms | 1.369× |
| Flash preprocess `[4,16,8192,128]` f16 | 50.371 ms | 4.369 s | 86.736× |
| DYT `[4096,4096]` f32 | 996.396 ms | 1.237 s | 1.242× |
| Liger RMSNorm `[2048,4096]` f32 | 26.096 ms | 128.059 ms | 4.907× |
| LayerNorm `[4096,4096]` f32 | 197.427 ms | 343.474 ms | 1.740× |

七项几何平均为 `4.349×`。GeGLU 已通过同源 Q，并有 natural-shape quick 结果，但测量预算与七项不同，故不混入
aggregate。这里的结论是：直接迁移能够工作，但会保留 GPU 风格 block/unroll 结构；J-grounded RVV lowering
可以形成更紧凑的 dynamic-VL loop。它不是全量 Triton-CPU baseline。

## 5. ggml 与 Expert RVV

ggml 的统一 formal 子集是 SwiGLU、DYT、Softmax、xFormers RMSNorm，`ggml / Full` 分别为
`0.236× / 1.050× / 1.617× / 2.610×`，几何平均 `1.011×`。GeGLU 另有 quick 结果。SwiGLU 是明确负例：
ggml 快约 4.24×。

Expert RVV 只为严格匹配、能够公平比较的四项提供动态 VL intrinsic。不存在的实现保持 N/A，不用临时拼出的
C 循环冒充成熟实现。

## 6. 论文还能缺什么

1. 完成其余 17 项正式 J 的 RVV `C-Fixed / Schedule-Only / Full`；这是跨目标主张最大的缺口。
2. 用统一 `rv64gcv_zfh_zvfh` flags 重测旧四项 LLVM-RVV C 配对，再计算七项外部 aggregate。
3. 为 Llama4 RoPE 收紧 segment/interleaved codegen；当前 Full 慢于 LLVM-RVV C 约 1.63×。
4. 优先修 Flash one-pass LayerNorm 的 f16 vector producer/epilogue；当前 Full 慢于 LLVM-RVV C 约 4.88×。
5. 为 Flash Linear 补高性能 K blocking/contraction path；正确 generic lowering 不等于有竞争力。
6. 继续扩展严格可执行的 Triton-CPU 与 ggml/Expert 子集，但不把 N/A 当失败，也不伪造全覆盖 baseline。

现有 Triton-CPU 与 ggml 配对数据位于
`doc/results/rvv-external-baselines-20260801/`。它们不含被删除的两个 TileLang 输入，仍可使用。
