# 已通过 22 个 J：三目标后端总览与 `52.201×` 解释

日期：2026-07-31

本文把阶段一 Fresh-14 与阶段二新增 8 项放回同一张后端地图中。固定使用：

```text
C-Fixed
Schedule-Only
Full
Source（GPU）/ Native（RVV）
G_schedule = C-Fixed / Schedule-Only
G_full     = Schedule-Only / Full
```

## 1. 总结论

当前已经成立的是：

1. `doc/J来源.md` 中的 22 个 accepted J 均已进入后端工作范围；
2. 5090D、H100 已有 22/22 的 `C-Fixed / Schedule-Only / Full / Source` 完整结果；
3. 两张 GPU 表中，22/22 的 Full 均不慢于对应 Source；
4. 阶段二新增 8 项已经在 5090D、H100、RVV 单线程全部完成；
5. RVV 的阶段一 Fresh-14 尚未形成 14 项统一正式矩阵，因此目前不能声称 RVV 已有 22/22 完整性能表；
6. 阶段二 5090D 的 `G_full=52.201×` 是内部 `Schedule-Only / Full` 几何均值，不是相对 Triton Source 的
   加速；同一批的 `Source/Full` 几何均值是 `1.364×`。

把阶段一和阶段二的 GPU 几何均值按 kernel 数合并，可得到以下总览。这里的“22 项合并”只用于看全局状态，
不能替代逐项结果：

| Target | 范围 | `G_schedule` | `G_full` | Source/Full | `G_full >= 1.50×` |
|---|---|---:|---:|---:|---:|
| 5090D | 阶段一 14 项 | 1.168× | 1.073× | 1.261× | 1 |
| 5090D | 阶段二 8 项 | 1.064× | 52.201× | 1.364× | 6 |
| 5090D | 22 项合并 | ≈1.129× | ≈4.406× | ≈1.298× | 7 |
| H100 | 阶段一 14 项 | 1.197× | 1.185× | 1.373× | 2 |
| H100 | 阶段二 8 项 | 1.065× | 89.373× | 1.445× | 7 |
| H100 | 22 项合并 | ≈1.147× | ≈5.707× | ≈1.399× | 9 |

最稳妥的总判断是：

- 外部竞争力：22 项 Full 相对 Source 的几何均值约为 `1.298×/1.399×`；
- C 解冻：全 22 项 `G_schedule` 约为 `1.129×/1.147×`，价值存在但不是每项都大；
- 结构路径：阶段一是少量强 cell 加大量物理负例；阶段二把 6--7 个此前停在 generic materialization 的 J
  接入了真正的专用 C++/MLIR lowering，因此 `G_full` 非常大；
- RVV：阶段二 8 项的 `G_schedule=1.769×、G_full=1.792×`，但阶段一矩阵不完整，不能计算 22 项总值。

## 2. `52.201×` 到底是什么

### 2.1 计算没有错误

阶段二 5090D 八项的 `G_full` 是：

| Kernel | Schedule-Only (us) | Full (us) | `G_full` | Source (us) | Source/Full |
|---|---:|---:|---:|---:|---:|
| JSD | 149550.278 | 181.088 | 825.843× | 197.232 | 1.086× |
| TVD | 182.176 | 182.176 | 1.000× | 201.744 | 1.109× |
| xFormers RMSNorm | 71937.981 | 270.272 | 266.169× | 283.904 | 1.048× |
| CrossEntropy | 5211.520 | 22.688 | 229.704× | 43.104 | 1.896× |
| GroupNorm | 463.296 | 15.296 | 30.289× | 33.328 | 2.174× |
| Liger RoPE | 4911.648 | 40.320 | 121.817× | 55.312 | 1.370× |
| Qwen2VL MRoPE | 15384.416 | 54.976 | 279.839× | 65.392 | 1.184× |
| Flash Linear | 150.880 | 142.656 | 1.058× | 203.392 | 1.422× |

几何均值为：

```text
exp((ln 825.843 + ln 1.000 + ln 266.169 + ln 229.704
     + ln 30.289 + ln 121.817 + ln 279.839 + ln 1.058) / 8)
= 52.201
```

它被 JSD、xFormers RMSNorm、CrossEntropy、Liger RoPE、Qwen2VL MRoPE 五项主导，不是八项都均匀获得
52 倍。TVD 完全没有 Full 增益，Flash Linear 在 5090D 上只有 `1.058×`。

### 2.2 为什么内部是 52 倍，而相对 Source 只有 1.364 倍

`Schedule-Only` 不是 Source。它固定 DirectLower(J) 的 executable structure，只搜索 tile、threads、warps、
vector、pipeline 等参数。阶段二的多个 J 在该固定结构中仍是 generic materialized 路径：保留了中间 tensor、
多次完整 traversal 或多次 dispatch。仅靠 retile 无法删除这些工作。

Full 才进入以下真实 MLIR 路径：

- JSD、xFormers RMSNorm、CrossEntropy、GroupNorm：单 kernel read-once row reduction；
- Liger RoPE、Qwen2VL MRoPE：N-D paired rotation，同时产生两个 observable output，不物化 split/concat/gather；
- Flash Linear：真实 `mma.sync` contraction；
- TVD：canonical 路径本来已经是单遍 elementwise，因此没有新的结构空间。

原始 Triton Source 本身已经是面向这些算子的高性能 fused implementation。因此会出现：

```text
JSD:
  Schedule-Only generic spine  = 149550.278 us
  Full read-once path          =    181.088 us
  Triton Source                =    197.232 us
```

所以这三个数字同时是合理的：

- `825.843×` 说明固定 generic structure 的 schedule search 无法替代结构 lowering；
- `1.086×` 说明最终 Full 只比已经很强的 Source 快 8.6%；
- Full 达到 Source 附近或更快，说明巨大内部差值没有以牺牲最终竞争力为代价。

### 2.3 `52.201×` 能证明什么、不能证明什么

它能够证明：

- 同一个 J 下，固定 structure 的 schedule search 与开放结构路径不是一回事；
- materialization、traversal、dispatch、index graph 或 contraction path 的改变可产生 tile search 无法达到的结果；
- 这些 Full executable 来自 C++/MLIR pass，不是 Python target-kernel emission。

它不能被写成：

- “IntentIR 比 Triton 快 52.201×”；
- “每个 kernel 平均都快 52 倍”；
- “所有收益都来自新的算法”；
- “canonical backend 已经足够成熟”。

事实上，这个数字同时暴露出阶段二 canonical spine 很弱。它适合作为内部解耦证据，但外部 headline 必须使用
`Source/Full=1.364×`，并展示逐项结果。后续若增强 deterministic DirectLower 而不提前放入搜索型结构，
`G_full` 可能下降；这不代表最终后端退步，而代表基础 emitter 变强。

机器报告中的直接核查位置为：

```text
doc/results/stage2-new8-production-backend-22/5090d/*.json
  kernels[0].performance.schedule_spine_ablation
  kernels[0].winner
  kernels[0].candidates[*].transformation_record
```

其中记录了同轮 measurement、Schedule-Only spine、Full winner、实际 pass、launch 和编译后结构。

## 4. 22 个 Kernel 当前真正消费了什么

| 结构类别 | Kernel | 当前 GPU 状态 | 当前 RVV 状态 |
|---|---|---|---|
| 单遍 elementwise | SwiGLU、GeGLU、DYT、TVD | vectorized/fused 单遍；多数 Full 接近 1 | TVD 已形成 producer-consumer fused scalable-vector；阶段一三项未形成正式全表 |
| normalization / statistics | RMSNorm、Fused Add RMSNorm、LayerNorm、PolyNorm、xFormers RMSNorm、xFormers RMSNorm-add、Flash one-pass LayerNorm、GroupNorm | read-once row reduction、joint/multi-accumulator 或 grouped statistics | 已有 scalable-vector、explicit reduction、joint statistics、raw moment；不同 kernel 完成度不同 |
| stable / multi-input reduction | Softmax、KLDiv、JSD、CrossEntropy | stable/read-once、gather/effect 与多输出路径 | JSD 已融合；CrossEntropy 仍为 materialized fixed-vector；阶段一 Softmax/KLDiv 正式矩阵未闭合 |
| prefix / scan | Sparsemax | prefix/frontier/tau 路径已形成强结果 | 尚无专用 prefix/segmented-scan lowering |
| padded reduction | Flash backward preprocess | subgroup-feature 与多行 live accumulator | padded/masked packet 尚未形成 Fresh-14 正式结果 |
| N-D indexed rotation | Liger RoPE、Qwen2VL MRoPE | paired rotation、双输出、消除 split/concat/gather materialization | 仍为 materialized fixed-vector，是明确缺口 |
| contraction | Flash Linear | canonical tiled contraction；Full 可进入真实 `mma.sync` | 正确 generic scalable-vector contraction；尚无专用 K blocking/高性能 contraction path |
| weighted merge | SplitK reduce | 单 CTA/多 warp 与跨 CTA D partition | producer 不在 J boundary 时保守保留，Fresh-14 正式矩阵未闭合 |

这里的“消费”指 accepted J 被 materialize 为 typed Intent MLIR，C++ pass 按 op、shape、dtype、domain、
reduction/index/dataflow 匹配并生成目标代码。Python 只负责状态枚举、Q/D、编译编排与计时，不发射 CUDA/RVV
kernel。后端 matcher 不读取 kernel 名或 Source 路径。

## 6. Workload 与证据边界

所有当前正式 GPU 数据采用 code-warm/data-cold：代码已编译和加载，数据在每个样本前做 L2 eviction，计时区间
只包含 prepared launch，CUDA event 计时。RVV 固定 CPU affinity、单线程、code-warm/data-cold。

阶段二 8 项的 natural/model-level shape 与 dtype 已完整记录在：

```text
doc/results/stage2-new8-production-backend-22/README.md
```

阶段一最终汇报包含 14 项 GPU 完整性能表，但仓库内的最终汇报没有逐项汇总全部 headline shape/dtype；已有明确
记录包括 Flash preprocess `[4,16,8192,128]`、Softmax/Sparsemax `[2048,4096]`、SplitK
`[1,1,16,1,256]`，以及 RVV PolyNorm `[2048,4096]`、LayerNorm/Flash one-pass LayerNorm
`[4096,4096]`。其余项不在本文猜测具体数值。

这是结果可读性缺口，不推翻现有 GPU timing；但在形成最终论文图前，应从当时可执行 workload report 补回精确
shape、dtype 和 observable boundary，而不是拿 closure valuation 代替 natural workload。

## 7. 目前可以写出的结论

可以写：

- 22 个 accepted J 已在 5090D/H100 被同一 production backend 真实消费；
- C 作为 non-binding prior，解冻后在全 22 项带来约 `1.13×/1.15×` 的 target retile 几何均值；
- Full 在多项 kernel 中打开固定 schedule 到不了的 materialization、traversal、reduction/index graph 与 MMA 路径；
- 最终 Full 在两张 GPU 上相对原始 Source 的 22 项几何均值约为 `1.30×/1.40×`；
- 同一个 J 在 GPU 与 RVV 上选择了不同 concrete MLIR 路径，跨目标复用已经有直接实例。

不能写：

- “比 Triton 平均快 52×/89×”；
- “RVV 已有 22 项完整正式矩阵”；
- “所有 22 项都从 Full 得到大幅收益”；
- “所有阶段二巨大 Full 收益都是算法创新”；
- “仅凭 requested flag 就证明某个路径已被消费”。

## 8. 当前最重要的后端缺口

1. **提高 canonical DirectLower 的基本质量**：阶段二若干 generic spine 极慢。必须保持 C-Fixed/Schedule-Only
   的结构边界，但基础 emitter 不应因多余 dispatch/materialization 造成不必要的病态结果；
2. **补 RVV N-D indexed/in-place fusion**：Liger RoPE 与 Qwen2VL MRoPE 当前仍明显慢于 Native；
3. **补 RVV contraction**：Flash Linear 已正确执行自然 `1024×1024×8192`，但没有专用 K blocking 或高性能
   contraction lowering；
4. **补 RVV CrossEntropy gather/effect fusion**：当前 Full 与 Schedule-Only 相同；
5. **完成 RVV Fresh-14 正式矩阵**：这是形成真正 22 项三目标横向结论的最大实验缺口；
6. **统一补回阶段一 workload 元数据**：只补论文可复核所需的 shape/dtype/output boundary，不做无关冻结材料。
