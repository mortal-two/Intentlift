# 高级 AI 对三份核心设计的复审与四项修正

> 性质：2026-07-22 外部复审意见与吸收记录，不是独立规范。
> 对应提交：`95f7c7d docs: close core design validation boundaries`

## 总体判断

复审认为 C、π 与最终执行流程已经形成相互支持的整体，不应继续推翻或扩张设计。当前主关系为：

```text
Lift_H(S) = (J,C,pi)
Replay = W_f(J,pi,MaskC(C);U_f)
SCRC_CERTIFIED iff TypeCheck(J,C,pi) and Gate1 and Gate2
```

复审只提出四项需要闭合的边界。

## 1. interface 不能成为第四对象

logical signature 属于 J；input、output、runtime scalar、destination、dtype、rank、shape、
alias/inout/effect 都使用 J signature handle。π 的锚点只属于 `Ids(J) ∪ Ids(C)`。

工程若需要接口视图，只能使用 J 的确定性投影 `InterfaceView(J)`。它不独立序列化、不建立
新的 ID 命名空间，也不成为 Replay 的额外输入。

## 2. TypeCheck 只检查显式授权

TypeCheck 不应成为新的语义证明器。对 integer width、numeric cast、reassociation、atomic
form 等 sensitive refinement，它只检查：

```text
auth_ref(r) in Auth(J,B)
or kind(r) in GlobalSafeRefinement
```

否则 fail closed。Parametricity 也不能只比较 carrier，而应使用：

```text
RealSig(J) = (Carrier(J), Capabilities(J,B))
```

## 3. Gate2 及格线不能由候选放宽

B 只能选择系统支持的封闭 comparison class 并声明必要语义合同；系统比较协议构造实际
`equivalent_B`，检查 tolerance、NaN/Inf 和 allowed-result/atomic 等全部参数。不支持的类别或
非法参数 fail closed。Lift 不能注入任意 comparator、任意大 `rtol/atol` 或“所有输出均可接受”。

## 4. 隐藏随机 Gate2 的概率前提

Gate1 首次通过后，本次 Gate2 使用的 `(J,C,pi,Replay)` 不再修改；随后才从预先声明的分布 D
独立同分布抽取对 Lift/Replay 隐藏的输入，Gate2 结果不回流本次实验。只有此时，才能根据
Source–J 在 D 上的错误质量引用 `(1-epsilon)^m` 上界。

若只使用有限测试集合 T，只能声明在 T 上的三方一致性，不能引用随机 challenge 的概率结论。

## 实现落差

复审同时指出两项实现工作，但没有据此增加新对象或新 Gate：

1. 当前自闭合 parser 需要升级为最小 `TypeCheck(J,C,pi)`；
2. 旧 `masked hard-close -> LEAKAGE_REJECTED` 状态机需要拆成主认证、J 必要性和 TypeCheck 状态。

这些结论已经吸收到三份核心设计；本记录仅保存复审来源。
