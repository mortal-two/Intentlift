# IntentIR 多前端扩展现状与接入路线（更新于 2026-07-28）

## 1. 当前结论

TileLang/CUDA 已不再只是 catalog、compiler 和 observer 层面的“半接入”。当前
分支已经把它们接入正式 SCRC 生命周期：

```text
真实 Source + Harness compiler view
              |
              v
       source-aware Lift LLM
              |
           (J,C,π)
              |
              v
       source-blind Replay LLM
              |
              v
   frontend Compile / Observe / Run
```

Dataset 当前共有 66 个原生条目。通用投影机制能把其中 56 个机械地转换成可准备、
可编译的正式 Harness：26 个 TileLang factory、30 个 CUDA kernel。剩余 10 个是
5 个同时存在于 TileLang/CUDA 两侧的 `CUtensorMap` 家族；它们缺少可构造 opaque
descriptor 的显式 sidecar，因此保持 `case_unavailable`，没有猜测或伪造输入。

统一 registry 当前有 84 个 ready workload：28 个 Triton、26 个 TileLang、30 个
CUDA。这里的 “ready” 表示已具备正式 Harness 和真实前端编译入口，不表示 84 个
workload 已全部由 LLM 跑到 SCRC certified。

本分支没有增加 TileLang/CUDA -> J 的确定性算子 parser，也没有增加 J ->
TileLang/CUDA 的手写语义 lowerer。Source -> J 与 J/π -> Replay 仍分别由 source-aware
Lift agent 和 source-blind Replay agent 独立完成；固定代码只投影 ABI、shape、launch
与运行 fixture，不生成 J、算子图或 schedule。

## 4. 自动 Harness 投影机制

`project_frontend_dataset_harnesses()` 对整个 Dataset 使用同一套保守协议，只消费：

- 已导出的 CUDA ABI/interface/launch；
- TileLang factory 的 literal 默认参数；
- canonical concrete shape snapshot；
- handwritten CUDA 相邻 Python descriptor 中可由 `ast.literal_eval` 读取的 IO schema。

它明确不消费 `intent_seed`、semantic ops、schedule、kernel family 名或自然语言语义
标签。关键安全机制包括：

1. 每次准备 workload 前完整验证 catalog，并固定 Source SHA-256；TileLang generated
   companion 的 ABI/launch descriptor 也单独固定 SHA-256。
2. ABI `position` 必须是唯一、连续整数；参数 kind/dtype/rank/mode/scalar 值均做类型
   校验，非有限值被拒绝。
3. TileLang materialized source 的参数顺序可能与 generated CUDA ABI 顺序不同。
   投影器使用保守的 carrier alias 双射匹配 `*_handle`/`*_ptr`，按真实 Source 顺序
   构造 compiler/runtime arguments；匹配歧义时拒绝，不按位置静默错绑。
4. 不同符号维度始终映射为不同匿名 `h*` 坐标，即使有限测试值相等。例如 M/K/N
   都取 4 时仍是 `h0/h1/h2`，不会因值相等而合并数学维度。
5. launch 只允许受限整数表达式；不执行任意 Python。生成 fixture 使用稳定种子，
   index-like tensor 采用有界非负整数，但不根据参数名猜语义。
6. handwritten CUDA 的 pointer mode 由保守的直接下标 effect analysis 得出；pointer
   escape 或无法证明的用法会拒绝，而不是把所有 mutable pointer 当输出。
7. 临时 TileLang module 名只用稳定 SHA 前缀隔离 import；该 digest 仅用于工程隔离，
   不参与 TypeCheck、Gate1、Gate2 或认证判定。

56 个 ready case（包括两个早期 add2d canary ID）全部使用同一投影协议，没有按
case-id 回填 fixture，也没有每算子注册表。两个手写 add2d Harness 只保留给独立的
固定 artifact/static Replay GPU smoke test，不参与 corpus-wide registry 投影。

## 5. 架构职责边界

- J 只表达前端无关的逻辑语义。
- C 只保存独立、纯净的实现选择值。
- π 只保存匿名 realization witness，不可执行。
- Harness 独占 Source 位置、原始名字、具体 shape/value、launch 和 fixture。
- Gate1 比较 Source 与 Replay 的前端 observer 投影。
- Gate2 比较 Source、Replay、RefEval(J) 三条执行边。
- 生产后端只消费 J+C，不消费 π。
- fixed code 可以校验和匿名化 ABI，但不能从 Source 生成 J，不能从 J 生成算子实现。

## 6. TileLang 的正确观察边界

TileLang 的主比较层是 TIR，不是 PTX。当前 profile 为：

```text
tilelang-tir-semantic-structure-ptx-diagnostic-v3
```

硬比较保留：

- 参数 interface/schema；
- loop 数量、嵌套、边界与 body；
- buffer shape、索引、读写 effect、控制结构和数学运算；
- `blockIdx/threadIdx` launch topology；
- PTX schema/interface/target。

只将 `T.parallel`、`T.serial`、`T.vectorized`、`T.unroll`、`T.pipelined` 与
`T.thread_binding` 的 iterator spelling 规范化为同一个语义 `range`。原因是公开
`(J,C,π)` 当前没有字段携带这项 source realization spelling，source-blind Replay
无法唯一恢复它。loop bound、body、index 或 effect 的任何变化仍是硬失败。

PTX 的其余 opcode/instruction topology 只作 diagnostic，因为 TileLang -> TIR -> CUDA
lowering 可以对同一 TIR 语义产生不同低层 spelling；这不等于放松 TIR 数学结构。


TileLang run 的 `inconclusive` 不是 masked Replay 闭合：masked 分支编译成功后，PTX

`SCRC_CERTIFIED`；不能把该次 run 误报成 “J necessity proved”。

上述两个 provider run 的 receipt 是当时主线的 Codex Replay v14。其后合入的 v15
只改变 source-blind packet 的有界读取方式；本分支已对 v15 做仓库回归，但没有为了
版本号重复消耗一次 provider run。因此 provider 证据与当前代码版本边界必须明确
区分。

## 8. 使用入口

列举统一 registry：

```bash
PYTHONPATH=python python tools/scrc_frontend.py --list --json
```

运行一个正式 native workload：

```bash
PYTHONPATH=python python tools/scrc_frontend.py \
  --case tilelang:add_bias2d \
  --dataset-root /home/kingdom/phdworks/Dataset/TianchenIR-MultiFrontend \
  --lift-backend codex \
  --replay-backend codex \
  --json
```

`--dataset-root` 同时接受 Dataset 父目录和 `TianchenIR-MultiFrontend` 项目目录。
Dataset 缺失时，`--list` 仍会保留 28 个 Triton case，并输出结构化
`native_unavailable` diagnostic。

batch 对一次 native case wave 只投影一次 Dataset registry，并把同一不可变 Harness
映射复用于 selection 与逐 case preparation；显式 Triton-only wave 完全不加载 native
Dataset。这样横向扩展不会随 case 数量重复全库扫描。

## 9. 下一步

1. 为 `CUtensorMap` 增加显式 descriptor sidecar、构造器与 runner，消除剩余 10 个
   unavailable case。
2. 按算子波次运行真实 provider，记录 certified/no-closure/infra-failure；ready 与
   certified 必须分开统计。
3. 修复通用 PTX observer 对 braced/predicated 指令的解析，使 masked-J 反事实可以
   给出 proved 或 failed，而不是 observer-induced inconclusive。
4. 如果某类 Replay 反复失败，优先检查 J/π 是否缺少表达所需事实、source-blind
   query 是否能有界消费已有事实、observer 是否比较了不可由公开证明对象恢复的
   spelling；不在 kernel 名上打补丁。

## 10. 非目标与禁止项

- 不把 CUDA snapshot 当作 TileLang 的语义真值。
- 不从 factory 参数名猜运行时 ABI 或 J。
- 不把 schedule/topology 偷塞入 J。
- 不让 π 成为可执行 IR。
- 不让投影器读取 `intent_seed` 或 semantic-op sidecar。
- 不因为 prepare/compile 成功就宣称 SCRC certified。
- 不在缺少 descriptor sidecar 时伪造复杂 opaque 参数。
- 不用 digest、receipt 或随机哈希替代数学证据。
