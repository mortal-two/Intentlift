# IntentIR 多前端扩展现状与接入路线（2026-07-26）

## 1. 结论

仓库此前已经具备 TileLang/CUDA 的 Dataset catalog、原生编译器、Gate1
observer 和 Gate2 runner，但它们尚未进入正式 SCRC 生命周期。具体缺口是：

1. 正式 workload preparation、Lift runtime 和 CLI 仍只接受 Triton；
2. Lift 的匿名化入口只处理 Python AST，CUDA 源码无法进入 Lift；
3. Replay 虽有 CUDA/TileLang 代码提取器，正式 ingress、MiniSWE 和合成编译检查
   仍按 Triton-only 处理；
4. `FrontendDatasetKernel` 只到 catalog/compile/snapshot 层，没有生成
   `SCRCRunRequest`，也不会进入 `SCRCGateRunner`；
5. Dataset 元数据尚不足以对全部 66 个原生条目自动生成可靠运行 fixture。

因此，“多前端已经接入”只能描述此前的编译和观测基础设施，不能描述
Source -> Lift -> `(J,C,π)` -> source-blind Replay -> Gate1 -> Gate2 的闭合。

本分支以两个同语义真实样板闭合第一条纵向切片：

- `tilelang:add2d`：真实 TileLang factory；
- `cuda:tilelang_add2d`：该 factory 由 TileLang 0.1.8 导出的真实 CUDA snapshot。

两者现已进入同一 PreparedWorkload、Lift/Replay、Gate1/Gate2 runtime 和
frontend-neutral registry。这里没有引入 TileLang/CUDA 到 J 的确定性 parser，
也没有引入 J 到前端的手写 lowerer。

## 3. Dataset 事实

Dataset 根目录：

```text
/home/kingdom/phdworks/Dataset/TianchenIR-MultiFrontend
```

当前 catalog：

| 前端 | 数量 | 组成 |
|---|---:|---|
| TileLang | 31 | 31 个真实 factory |
| CUDA | 35 | 4 个 handwritten + 31 个 TileLang CUDA snapshot |

31 个生成 snapshot 均有 `interface`、`cuda_abi` 和 `launch` 元数据。对这
31 份 snapshot interface shape 的扫描结果显示：

- 27 个条目含符号维度，4 个条目完全静态；
- 5 个条目使用 `CUtensorMap` descriptor，需要显式 fixture sidecar；
- Dataset 尚无统一的输入生成、索引/掩码、scale、descriptor fixture sidecar；
- 部分复杂 `ceildiv` launch 表达式在 snapshot 元数据中被截断，不能盲目求值；
- factory 参数描述构造/调度，不能误当成运行时 kernel ABI。

因此，当前正确策略是先闭合有明确 ABI 和有限 fixture 的 canary，再扩展
通用 shape binding 和 sidecar，而不是对 66 个条目伪造默认输入。

## 4. 必须保持的架构边界

新增前端遵循 SCRC 的既有职责划分：

```text
真实 Source + Harness compiler view
              |
              v
       source-aware Lift LLM
              |
           (J,C,π)
              |
              v
       source-blind Replay U_f
              |
              v
   frontend Compile / Observe / Run
```

其中：

- J 只表达前端无关逻辑语义；
- C 只保存独立、纯净的实现选择值；
- π 只保存匿名 realization witness，不可执行；
- Harness 独占真实源码位置、原始名字、具体 shape/value、launch 和 fixture；
- Gate1 比较 Source 与 Replay 的 observer 投影；
- Gate2 比较 Source/Replay/J 三条执行边；
- 生产后端只消费 J+C，不消费 π；
- 前端接入不要求 J -> TileLang/CUDA lowerer，也不定义前端的完整形式语义。

## 5. 本分支已实现的纵向切片

### 5.1 Lift

- CUDA 增加安全的 lexical ABI 匿名化：entry 固定为 `scrc_k0`，位置参数固定为
  `p0,p1,...`，注释和字符串不被替换；
- 正确处理 snapshot 常见的“forward prototype + 带 `__launch_bounds__` 的唯一
  definition”；
- Lift provider adapter、Responses relift 和 MiniSWE Lift 均显式携带 frontend；
- TileLang factory 在 Harness 内物化为真实 TIR script，作为 Lift 可见 Source；
  Gate1/Gate2 仍使用原始 factory，而不是 CUDA snapshot 替代它。

### 5.2 Replay

- CUDA/TileLang 正式进入静态 ingress；
- Responses 和 MiniSWE Replay writer 均按 frontend 选择公开 U_f；
- source-blind synthetic compile check 为 CUDA/TileLang 构造仅来自 J.signature
  的公开 ABI，不读取 Source 或 Harness；
- CUDA Replay validator 受控支持 `__launch_bounds__(...)`，仍保留单一
  `__global__` entry、设备 helper 和公开 header 白名单。

### 5.3 Harness 与 runtime

- 新增 `FrontendDatasetHarness`、`DatasetRuntimeParameter`、
  `PreparedFrontendDatasetWorkload`；
- workload preparation 在执行 TileLang factory 前强制通过完整 catalog
  validation，并校验注册 Harness 固定的源码 SHA-256；
- 从 snapshot 的 `cuda_abi` 绑定 dtype/rank/mode/shape/scalar；
- 从受限整数表达式绑定 launch；不执行任意 Python；
- TileLang/CUDA 使用各自原生 Gate1 compiler/observer；
- TileLang/CUDA 使用各自原生 Gate2 Source/Replay runner，并共享同一 RefEval(J)
  与外部 Q；
- 新增 frontend-neutral workload registry；当前注册 28 Triton + 2 native
  canary；
- 新增 `tools/scrc_frontend.py`，可统一列举和运行注册 workload；
- 固定 artifact Gate1 recheck 已改为使用统一 registry。

## 6. 验证结果

Dataset 基线：

```text
tilelang=31, cuda=35, errors=[]
```

准备后的真实 Source 编译：

```text
tilelang:add2d       compile=true
cuda:tilelang_add2d  compile=true
```

使用固定合法 `(J,C,π)` 和 source-blind static Replay 进行完整执行验证：

```text
tilelang:add2d       Gate1=replay_closed  Gate2=gate2_pass
cuda:tilelang_add2d  Gate1=replay_closed  Gate2=gate2_pass
```

这次验证真实执行了两种前端的 Source 和 Replay GPU 程序，也执行了 RefEval(J)。
它验证固定生命周期接线，不替代正式 LLM Lift/Replay 试验。

可复现的 GPU smoke test 为：

```bash
INTENTIR_RUN_NATIVE_DATASET_SMOKE=1 PYTHONPATH=python pytest -q \
  python/tests/test_frontend_workloads.py::test_native_dataset_add2d_closes_real_gate1_and_gate2
```

当前环境结果：`1 passed`。

新 worktree 需要与源码匹配的工具：

```bash
cmake -S . -B build -G Ninja \
  -DMLIR_DIR=/usr/lib/llvm-20/lib/cmake/mlir \
  -DLLVM_DIR=/usr/lib/llvm-20/lib/cmake/llvm \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build --target intent-opt -j 8
```

其他 worktree 的旧 `intent-opt` 缺少 `-expand-rsqrt-for-libm`，不能作为本分支
Gate2 RefEval 的替代品。

## 8. 后续扩展顺序

1. 为无 descriptor 的 elementwise/reduction 条目增加结构化 Harness sidecar；
2. 扩展受控 shape/launch 表达式求值器，并修复 snapshot 端复杂表达式的完整保存；
3. 为 mask/index/scale 等非随机输入增加有类型 fixture 生成规则；
4. 为 `CUtensorMap` 等 opaque ABI 增加显式 descriptor sidecar 与 runner 支持；
5. 每增加一类 ABI，先用固定 artifact + static Replay 跑 Gate1/Gate2 接线验证，
   再运行正式 LLM Lift/Replay；
6. 最后将稳定的 native case 集合并入批量 manifest，而不是一次性宣称 66 个条目
   全部闭合。

## 9. 当前非目标

- 不把 CUDA snapshot 当作 TileLang 语义真值；
- 不从 factory 参数名猜测运行时 ABI；
- 不从参数名或位置猜测 J；
- 不把 schedule/topology 塞入 J；
- 不让 π 成为可执行 IR；
- 不因为 compile 成功就宣称 SCRC certified；
- 不在缺少 fixture sidecar 时对复杂 Dataset kernel 伪造随机输入。
