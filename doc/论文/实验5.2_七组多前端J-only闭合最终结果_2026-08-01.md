> TileLang/CUDA pairs；62/62 unique frontend runs

> 说明：本文档取代 2026-07-30 实验设计稿中的 2-pair/26-runnable 等中间口径。
> 后续 paired-J 分层分析：`TileLang_CUDA二十对J差异与多前端实验定稿_2026-08-01.md`；正文采用

## 1. 本实验要证明什么

本实验只回答一个有限而可证伪的问题：

> 当 TileLang 与 CUDA Source 被作者化为各自真实的 `(J,C,pi)` 后，fresh
> source-blind Replay agent 能否只消费 `J + MaskC(C) + U_f`，在不读取 Source、pi、
> Gate feedback 或历史 Replay 的情况下，为同一组开放世界语义生成可执行 Replay，并通过各自正确的
> Gate1 observer 与三边 Gate2？

它对应论文的扩展性主张：前端语法、ABI 与 realization 的碎片化被隔离在 Source projection、C、
observer 和 native runner；计算语义进入 J。Replay 不需要按 `frontend × kernel` 获得答案模板，且本批
实验没有新增 kernel-specific production semantic lowering。

本实验不测 Lift agent 的恢复质量：为消除 Lift 速度与正确性的混杂，所有 artifact 均由主代理直接审计
Source 后手工作者化，`lift_agent_calls=0`。它也不单独证明 backend target performance；后端 lower/search
结果应由后端分支的独立实验报告。

## 2. 分母与预注册 cohort

数据集有 31 个带相同 `origin_case_id` 的 TileLang/CUDA pair。另有 4 个 handwritten CUDA case，
但没有 same-origin TileLang Source，因此没有伪造配对。为了覆盖七种正交语义/实现压力，实验在运行前
冻结 7 个 cohort，每组 10 个 membership；cohort 之间允许重叠，组内不重复，七组并集恰为全部 31
个 unique pair。

因此全文必须同时报告三种分母：

| 统计单位 | 数量 | 含义 |
|---|---:|---|
| Cohort memberships | 70 | 7 个预注册组 × 每组 10；同一 pair 可属于多个组 |
| Unique pairs | 31 | 31 个 same-origin TileLang/CUDA 语义 pair |
| Unique frontend runs | 62 | 每个 pair 的 TileLang 与 CUDA 各自独立运行一次 |

“70/70”不能写成 70 个 unique kernels；闭合率的唯一无歧义写法是：

> **70/70 memberships, covering 31/31 unique pairs and 62/62 unique frontend runs.**

## 3. 协议

每个 frontend run 使用相同的正式协议：

1. 主代理读取 current Source、descriptor 和 compiler observation，直接构造 frontend-specific
   `(J,C,pi)`；不调用 Lift agent；
2. Decode/TypeCheck 完整 artifact；
3. 建立 fresh Codex Replay episode，模型为 `gpt-5.6-sol`、effort 为 `xhigh`、composer mode 为
   `off`；
4. Replay workspace 的根 payload 严格为 `j,c,u_f`；`pi`、Source、Harness valuation、Gate
   observation、prior/sibling Replay 不可见；
5. 每个正式 run 恰好一次 physical provider call；不跨 case 复用 conversation 或 candidate；
6. TileLang 的 hard observer 是 TIR semantic structure，PTX 只作 diagnostic；CUDA 的 hard
   observer 是 semantic PTX，raw PTX 只作 diagnostic；
7. Gate1 闭合后，使用 exact accepted Replay 运行 Source--Replay、Source--J、Replay--J 三边
   Gate2；每个 case 使用独立 `spawn` 进程，避免 CUDA context 污染；
8. Gate2 隔离重检不调用 Replay agent，也不把 Gate2 feedback 反馈给 agent。

该协议验证的是 J 是否足以主导 Replay，而不是 pi 是否能提示答案。`pi_visible_to_replay=false` 是每个
run 的机器记录，不是事后人工声明。

## 4. 总体结果：七组均为 10/10

| Cohort | 覆盖压力 | Closed memberships |
|---|---|---:|
| G1 | pointwise / selection | 10/10 |
| G2 | reduction / statistics / normalization | 10/10 |
| G3 | contraction / epilogue | 10/10 |
| G4 | attention / masking | 10/10 |
| G5 | indexing / layout / image | 10/10 |
| G6 | fusion / composition | 10/10 |
| G7 | cross-feature stress | 10/10 |
| **Total** | **70 memberships / 31 unique pairs / 62 unique runs** | **70/70** |

31 个 unique pair 的 TileLang 与 CUDA 两边均满足：

- TypeCheck PASS；
- fresh J-only Replay Gate1 `replay_closed`；
- 三边 Gate2 PASS；
- `lift_agent_calls=0`；
- `pi_visible_to_replay=false`。

这比只展示 add 或若干简单 pointwise case 更强：集合同时包含 reduction、normalization、间接寻址、
attention、contraction、fused epilogue、MLP、layout/image 与多 feature composition。

## 5. 最难子实验：五对 TensorMap/TMA contraction

最后闭合的 5 个 pair 是 `gemm`、`matmul_relu2d`、`matmul_bias_relu2d`、
`matmul_fused_epilogue2d` 和 `mlp2d`。它们的 CUDA Source 真实使用 by-value
`CUtensorMap`、TMA、swizzle、256-thread physical launch 与 dynamic shared memory；J 和 Replay
则保持逻辑 pointer ABI、128-thread logical launch 和零 dynamic shared memory。

物理 descriptor 由 71 行 declarative sidecar 提供，且只供 Source compile/run；每份 authoring
receipt 均记录：

```text
cuda_source_uses_sidecar_tensor_map = true
j_contains_tensor_map               = false
replay_contains_tensor_map          = false
```

这不是把 CUDA Source 的物理 ABI 错抹成 pointer ABI。相反，Source runner 接收真实
`CUtensorMap`，而 J/Replay 只表达同一计算的逻辑 tensor interface；Gate1 的 raw physical PTX ABI
保留为 diagnostic，hard interface 比较逻辑 artifact contract。

### 5.1 正式 Replay 结果

| Pair | CUDA Gate1 (s) | TileLang Gate1 (s) | CUDA Replay bytes | TileLang Replay bytes | Isolated Gate2 |
|---|---:|---:|---:|---:|---|
| gemm | 149.1 | 470.1 | 1,852 | 931 | both PASS |
| matmul_relu2d | 158.5 | 208.4 | 1,104 | 872 | both PASS |
| matmul_bias_relu2d | 169.7 | 267.4 | 1,179 | 989 | both PASS |
| matmul_fused_epilogue2d | 181.6 | 277.3 | 2,140 | 913 | both PASS |
| mlp2d | 169.1 | 368.5 | 1,125 | 1,467 | both PASS |

十个正式 Replay episode 的统计为：

- Gate1 wall time：median 195.0 s，mean 242.0 s，range 149.1--470.1 s；
- CUDA median 169.1 s；TileLang median 277.3 s；
- accepted Replay source：median 1,114.5 bytes，range 872--2,140 bytes；
- physical provider calls：10（每个 run 恰好 1 次）；
- isolated Gate2 recheck：10/10 PASS，median 6.233 s，mean 6.144 s；
- Gate2 recheck 的 Replay agent calls：0。

因此结果支持“能够闭合”和“没有为每个 physical occurrence 手工生成巨大程序”；它不支持“LLM
Replay 已经足够快”。分钟级 Gate1 wall time 仍是明确的系统限制。

### 5.2 J 的跨前端一致与真实差异

实验从不要求 TileLang 与 CUDA 的 full J byte-identical。比较结果是分层的：

| Pair | TileLang/CUDA 共同 J sections | 保留的真实差异 |
|---|---|---|
| gemm | intent、node ids、boundary、scopes、storage、全部 dimension relations | signature/C 与物理 Source ABI |
| matmul_relu2d | 同上 | signature/C 与物理 Source ABI |
| matmul_bias_relu2d | 同上 | signature/C 与物理 Source ABI |
| mlp2d | 同上 | signature/C 与物理 Source ABI |
| matmul_fused_epilogue2d | storage 与全部 dimension relations | TileLang mask 为 i1；CUDA logical interface 保留 i8，并在 J 中显式 cast 为 i1 |

前四对共享相同数学/dataflow sections，但不是强迫 full-J 相等；fused epilogue 则诚实保留 Source
类型差异。这支持论文更准确的表述：**Layer-A 数学结构在 Source 允许时复用，ABI、boundary 和 typed
representation 的差异仍由各自 J/C 表达。**

### 5.3 TF32 不是放松语义，而是外部对称 Q

f32 tensor-core Source 与数学 RefEval 之间存在预期的 TF32 realization error。错误 Q 下的诊断显示：

- Replay--J 最大误差不超过 `3.58e-7`；
- 失败只发生在包含 physical Source 的两条边；
- 单层 contraction 最大误差约 `8.4e-4--9.6e-4`，MLP 最大误差约 `2.40e-3`。

这些数值来自对应 `run-002/gate2_pre_isolation.json` 中使用 default Q 的三边 comparison receipt；
它们保留为选择外部 numeric policy 的诊断证据，不进入最终 PASS 计数。

最终由 Source sidecar 显式选择外部 policy
`intentir.gate2.tf32-tensorcore.v1`：f32 使用 `rtol=0.02, atol=0.003`，其他 dtype 保持其既有
policy。三条边使用同一个对称 Q；J 不携带阈值，Replay 也看不到该选择。五个 CUDA Source 均真实
执行并与 reference 在该预注册 Q 下闭合。

这一区分很重要：Gate2 接受的是被实验协议显式授权的数值 realization，不是按失败 case 临时修改 J
语义，也不是只放松 Source--Replay 一条边。

## 6. 最难增量的工程量

以下数字使用 `git diff --numstat b4f1b6da..df95382c`。它们只表示从“前 26 个 runnable pair 已闭合”
到“最后 5 个 TensorMap/TMA pair 闭合”的增量，不是完整 TileLang/CUDA onboarding 总成本。

| 类别 | Add | Del | Net | 说明 |
|---|---:|---:|---:|---|
| Source adapter/runtime (`frontend_workloads.py`) | 489 | 47 | +442 | generic physical/logical ABI、descriptor launch 支持 |
| Gate1 generic observer/replay infrastructure | 79 | 29 | +50 | TMA/MMA semantic observation、arch/CFG/axis 修复 |
| Gate2 generic native execution/policy | 220 | 11 | +209 | descriptor encoding、per-leg ABI、process isolation、external Q |
| **Executable production Python** | **788** | **87** | **+701** | 不含 sidecar、实验脚本、Source snapshot、evidence、docs |
| Declarative TensorMap sidecar | 71 | 0 | +71 | 5 个 case 的物理 launch/descriptor 数据，不是 semantic lowering |
| Experiment authoring/runner/recheck Python | 472 | 5 | +467 | 438 行 manual artifacts + 34/-5 runner/recheck；不计 production |

若把 71 行 sidecar 也计入 runtime integration surface，则该增量为 `+859/-87, net +772`；论文
headline 应优先采用拆分后的三行，而不是混成一个数字。

生产 diff 中新增的 kernel-specific semantic lowering/template 为 **0 LoC / 0 rules**。case id 只出现
在 declarative sidecar 的 data binding 中；production loader 按统一 schema 读取 descriptor，Gate1/Gate2
逻辑按 frontend、typed ABI、opcode family 与 policy id 泛化，没有
`emit_gemm`、`fix_mlp` 或按 Source path 匹配的 recipe。

438 行 manual artifact authoring 是本实验为了绕开慢 Lift 而保留的可审计 J/C/pi 证据，不应伪装成
production compiler，也不能用它声称“新增 kernel 为零人工工作”。本实验真正支持的是：**新增这些
kernel 没有引入 kernel-specific production lowering；当前 manual semantic authoring 成本仍然存在。**

## 7. 论文可以写什么，不能写什么

### 可以写

1. 在预注册的七个 semantic/realization cohort 中，系统闭合 70/70 memberships，覆盖 31/31
   unique TileLang/CUDA pairs 和 62/62 independent frontend runs；
2. 所有 run 都由 fresh source-blind Codex 只消费 `J,C,U_f`，Lift 调用为 0，pi 对 Replay 不可见；
3. TileLang 以 TIR、CUDA 以 semantic PTX 作为各自 hard observer，没有错误地用 PTX textual equality
   比较 TileLang；
4. 最难的 CUDA Source 保留真实 TensorMap/TMA physical realization，而 J/Replay 使用 logical ABI，
   10 个 contraction/fusion frontend runs 仍全部闭合；
5. 该最难增量没有新增 kernel-specific production semantic lowering，新增能力集中在可复用 ABI、
   observer、native execution 与 numeric policy 机制；
6. 跨前端 J 是“共同数学核心 + 有 Source 依据的 typed/ABI delta”，而不是被人为强制 byte equality。

### 不能写

1. 70 个 unique kernels；真实分母是 31 pair / 62 frontend runs；
2. 任意 TileLang/CUDA kernel 都能闭合；结论只覆盖 measured dataset 与当前 GPU/toolchain；
3. Lift 已解决；本实验明确绕开 Lift，由主代理手工作者化；
4. Replay 已高效到可替代成熟编译器；最后 10 个 episode 的 median 仍为 195 s；
5. 完整多前端 onboarding 只需 701 LoC；701 是最后 TensorMap/TMA 增量的 executable Python net
   delta，不是系统总成本；
6. backend lower/search 性能已由本实验验证；该问题需要引用 backend 分支的独立证据。

## 8. 可直接进入正文的结果段落

> We pre-registered seven overlapping semantic and realization cohorts with ten
> memberships each. The 70 memberships cover all 31 same-origin TileLang/CUDA
> kernel pairs, yielding 62 independent frontend runs. All seven cohorts closed
> at 10/10. Every run used a fresh source-blind Codex episode that received only
> J, masked public configuration, and the public target contract; Lift was never
> invoked and pi was mechanically absent from the Replay packet. The hardest five
> pairs retained TensorMap/TMA, swizzle, warp-specialized launch, and dynamic
> shared memory as CUDA Source realization facts while exposing only a logical
> pointer ABI to J and Replay. Their ten Replays all passed frontend-appropriate
> Gate1 observation and isolated three-leg Gate2. Extending the already-closed
> corpus to these descriptor-backed kernels required 701 net lines of generic
> executable Python and 71 lines of declarative sidecar data, but no
> kernel-specific production semantic lowering rule. These results support
> factorization of frontend realization from shared computation semantics within
> the measured corpus; they do not claim zero manual J authoring or universal
> frontend coverage.
