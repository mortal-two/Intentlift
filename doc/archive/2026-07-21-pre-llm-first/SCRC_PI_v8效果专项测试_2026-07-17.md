> **masked-J 口径修正：** 本文最初把 `mask J -> recompose` 当成 π 反泄漏诊断，
> 该做法没有保留被测的实际 π 拓扑，不能回答 π 是否泄漏。当前 Gate1 已恢复

> 当时仍可能走已归档的 normal-candidate 复用通道，只能保留为旧协议结果，不能作为
> 当前 fresh counterfactual replay 的正式证据。旧的正式 `REPLAY_CLOSED` 结论也不能

1. π 是否真的是 `J + interface + C + RuleRegistry` 的确定性派生物？

3. paired J/B 干预是否会先修改 J、再重算 π，而不是修 replay code？
4. 实现机制替换是否只能从 `C.strategy` 发起，并在重算 π 后保持 J 语义？
5. π 是否对 opaque id、JSON key order 和独立节点声明顺序稳定？
6. 真实 LLM writer 的正向引导效果是否已经得到 v8 新证据？

## 3. 当前效果判断

### 3.1 已经有强证据的部分

π 的**协议正确性、可派生性和抗篡改性**证据较强：它不再是 LLM 可自由书写的
第二语义通道；同一权威输入只有一个 canonical π。旧的 step dropout、直接
mechanism substitution 已从“再问一次 writer 看是否退化”收紧为 writer 前精确拒绝。

`C.strategy` 的职责也已可观测：合法机制变化会导致确定性 π 改变，而 J、interface
和 C.schedule 不变。这比直接修改 π 更能证明“智能决策不住在 π 里”。

### 3.2 五核真实正向效果及当前证据边界

当前 v8 π 已获得五个目标 Kernel 的 fresh LLM normal 正向证据：五例均可生成、编译，
normal Gate1 硬指纹完全闭合，Gate2 通过。由于 writer 只看到 J/C/π/规则卡，这些
结果支持：

1. π 的步骤顺序和 target binding 足以把当前 J/C 组装成可执行施工合同；
2. 历史 paired J/B 干预能传递为精确 TTIR 变化，但 fresh-only paired 路径当前只有
   单元与集成回归证据，五核 live 因果数据需要重跑；
3. 合法实现差异能够放在 C.strategy，并由 composer 自动改变 π；
4. normal 路径不需要把源码文本或 replay 修复指令重新塞进 π。

这些结果尚不能证明 π 拓扑无泄漏；该结论必须由当前 actual-π masked-J terminal
attack 重新取得。若 masked replay 也硬闭合，即使 normal 与 Gate2 均通过，Gate1
仍应 `LEAKAGE_REJECTED`。

这仍是**五核证据**，不是数百 Kernel 的覆盖证明。尤其尚未覆盖复杂 loop carry、
多级 buffer lifetime、frontend scope、原子操作、scan、动态 rank、稀疏/间接访问等全部
特性。

### 3.3 本轮失败样例及原因

本轮没有隐藏失败；失败按阶段保留并推动了两处修正：

1. **add 的早期 Lift 失败**
   - 一次 provider `HTTP 500/EOF`，发生在返回 LiftArtifact 前，不计作 π 失败；
   - 后续模型把 scope definitions 写成 node/domain/access id，或给普通 op 写
     `scope_id`。根因是 J scope prompt 不够精确；收紧为 value handles/effect ids/仅
     semantic loop 可带 scope_id 后，add 正常闭合。
2. **row-sum 的机制替代误报 `generation_failed`**
   - 根因是实现仍给“C.strategy→recompose”路径传旧的 `ablation_kind`，但没有
     `plan_override`；这不是 writer 或 π 能力问题；
   - 删除旧耦合、按普通完整 π 调 writer 后，真实结果为 `semantics_preserved`。
3. **matmul 初次 Gate1 不闭合但 Gate2 通过**
   - 三轮 Gate1 最佳 score 从 0.571 提升到 0.818，仍有 `addptr/addi/muli/splat/
     expand_dims` 的 op/dataflow 差异；最终 Gate2 诊断为 pass，验证 Gate1 与 Gate2
     不是包容关系；
   - 源码按 `pointer + major_term + minor_term` 形成地址。旧
     `materialize_pointer_tile` 一方面允许 writer 先合并整数 offset，另一方面又允许
     把 coordinate 内部的 program-base/lane 过度拆开，施工规则不唯一；
   - RuleCard v3 收紧为：把 J domain coordinate 当原子，只按 index_expression 的
     顶层加法项从左到右各做一次 pointer addition，不拆乘法项和 coordinate 内部结构；
   - 不增加 π 字段、不复制源码拓扑，fresh matmul 随后首轮 Gate1/Gate2 全部通过。
4. **`fg_arange` 的 TTIR 关联差异曾诱导 Relift 污染 J**
   - 旧 Relift 把 sampled `BLOCK_SIZE`、block/lane 重建写入 J，错误地用算法层拟合
     source TTIR；
   - 新合同要求 layer correctness 优先于 Gate1 closure，并用 schema 约束保证
     `iota.n="size"` 不变成 sampled `1003`；
   - fresh schema-24 运行中两次 Relift 均保持 J/C/π 完全不变，最终
     `Gate1 NO_CLOSURE + Gate2 9/9 PASS`；剩余实现关联缺口等待计划外报告审查。

## 5. 当前结论

当前可以说：**π 已从可自由漂移的 LLM 字段变成确定性、可审计、可精确拒绝篡改
的施工协议；五核已有 normal Gate1 与 Gate2 正向历史证据。** paired intervention
的旧结果保留审计价值，但 current fresh-only 协议仍需五核 live 重跑。

当前不能再说五核已经在最新完整 Gate1 下全部闭合：add 已取得上述 actual-π
masked fresh 证据；row-sum、softmax、RMSNorm、matmul 仍需要 fresh 重放，不能由
历史 report 或 cache 静默升级。

当前不能说：**π 已经覆盖数百 Kernel 或全部复杂特性。** matmul 的修复也说明，后续
失败应优先判断 J schema、C.strategy 粒度与共享 RuleCard 是否足够确定，而不是让 π
重新承载算法或源码拓扑信息。
