## 4. 批处理入口

新增 `test/scrc_heldout_batch.py`，其流程固定为：

```text
真实 source-only compile preflight
  → live LLM Lift
  → Gate1 normal replay
  → masked-J
  → 仅 Gate1 正式闭合时进入正式 Gate2
```

工程能力包括：

- 逐 case 原子 JSON 报告，单个科学失败不会中止整个 sweep；
- 直接汇总现有 `lift_failed / compile_failed / no_closure /
  leakage_rejected / Gate2 status`，不创造新裁决指标；
- `--resume` 只在 source/compiler view、model/effort、seed、修复预算、诊断开关、
  规则库和 Lift prompt 均与当前运行一致时跳过已有 terminal report；旧 identity
  或缺 identity 的报告会重跑；
- `--lift-cache-dir` 只在 source hash、完整 compiler view、model、effort 和
  rule-registry digest、初始 Lift prompt hash 全部一致时复用真实 LLM artifact；
- `--diagnose-rejected` 只对已经存在 normal hard closure 的
  `LEAKAGE_REJECTED` 样本运行方案允许的离线 Gate2，对正式状态无覆盖作用；
- 默认模型与 effort 为 `gpt-5.6-sol / xhigh`。

当前 ready case 的 source preflight 均实际通过。批处理不会读取旧 corpus
`intent.json`，也不调用归档解释器。

## 5. 真实外部 Kernel 接缝修复

### 5.1 FlagGems `LibEntry`

FlagGems 的真实函数不是裸 `JITFunction`，而是：

```text
LibEntry → JITFunction
```

旧 Gate1 worker 直接读取外层 `constexprs`，导致 source preflight 失败。本轮
只沿受限 `.fn` wrapper chain 找拥有 `arg_names/constexprs/do_not_specialize`
的内层 JITFunction，并从 wrapper-specific warmup tuple 中提取唯一
CompiledKernel。真实 `dot_kernel` 编译回归已通过。

### 5.2 rank-0 tensor pointer

真实 dot/trace 的 output pointer 指向 rank-0 tensor。`SCRCCompilerArgument`
以前把空 shape 当成“缺 shape”，现已允许 tensor `shape=()`，compiler view
序列化为 `shape=[]`；scalar value 参数仍与 tensor pointer 严格区分。

### 5.3 TTIR scalar specialization

`fg_addr` 的完整 Python ABI 有 14 个 runtime 参数，但 Triton 将四个值为 1 的
普通 stride scalar 专门化并从 TTIR function signature 中消去。Gate1 现在：

1. 仍要求完整 Python `arg_names`、constexpr 位置与 CompileCase 精确一致；
2. 从 TTIR 读取 surviving argument name subsequence；
3. 允许没有 `tensor_ref` 的普通 shape/stride scalar 被专门化；
4. pointer/tensor 参数或连接 J 的语义 scalar 被消去时仍拒绝。

所以没有恢复此前被移除的 `do_not_specialize` 硬门禁，也没有放松 J/接口 dtype、
rank、mode 或 source/replay TTIR 比较。

## 6. `fg_dot`：真实 reduction 样本

配置：`N=1003, BLOCK_SIZE=1024`，x/y/output 为 f32，output rank 0，grid 1。

### 6.1 首次可审计 no-closure

v2 Lift 在一次 schema repair 后成功。三个 normal 候选都能编译并固定为
`score=0.5997412008`。J 已正确为：

```text
product = map_binary(mul, x, y)
out = reduce_sum(product, axis=0)
```

稳定 TTIR diff 只有两种源机制：

- FlagGems `tle.program_id` 将 program coordinate 显式扩到 i64，source 比 replay
  多三个 `arith.extsi`；
- source 使用 `tl.sum(tile)` 省略 axis，前端产生 `tt.reshape + tt.reduce`，
  replay 显式 `axis=0` 没有 reshape。

因此新增通用 `bind_wide_program_domain` 与
`realize_flattened_reduce`，没有加入 dot 专用模板或模糊规范化。

### 6.2 normal 闭合与 masked

新卡生效后，v4 normal 首候选 score `1.0`、全部硬项零差异。masked replay
同样完整猜中 dot，score `1.0`，所以最终为 `LEAKAGE_REJECTED`。

离线 Gate2：

| 比较 | 结果 | max abs error |
|---|---:|---:|
| source ↔ replay | PASS | `0.0` |
| source ↔ lowering | PASS | `2.6226043701171875e-6` |
| replay ↔ lowering | PASS | `2.6226043701171875e-6` |

该路径还验证 production Lower2C 能执行 rank-0 reduce output。

## 7. `fg_addr`：outer product、broadcast 与 runtime scalar

配置：`M=17,N=13,BLOCK_SIZE_M=BLOCK_SIZE_N=32`，三个 f32 输入、一个 f32
输出，runtime `beta=0.75`、`alpha=-1.25`，显式 input/vector/output strides。

J 使用现有 op：

```text
outer = contraction(vec1, vec2, "m,n->mn")
scaled_input = beta * input
scaled_outer = alpha * outer
output = scaled_input + scaled_outer
```

`alpha/beta` 是 J `shape=[]` 输入；M/N 与 stride scalar 不是 J tensor。

v1 先暴露 TTIR scalar specialization false reject。修复后复用同一真实 Lift
artifact，两个可编译 normal 候选稳定为 `0.7845735027`，第三个候选编译失败。
diff 显示：

- `m,n->mn` 没有 contracted label，π 却错误选择 K-tiled-dot；
- source 先构造并复用一维 `mask_m/mask_n`，replay 在二维 tile 上重复比较，
  因而多两个 `arith.cmpi` 并改变 expand-dims/dataflow。

新增 `realize_outer_product` 和 `materialize_mask_tile` 后，v3 Lift 首轮成功，
normal replay 首候选 score `1.0`。masked replay 未完全闭合，但 score
`0.7633866134 > 0.5`，正式状态仍是 `LEAKAGE_REJECTED`。

离线 Gate2：

| 比较 | 结果 | max abs error |
|---|---:|---:|
| source ↔ replay | PASS | `0.0` |
| source ↔ lowering | PASS | `4.917383193969727e-7` |
| replay ↔ lowering | PASS | `4.917383193969727e-7` |

## 8. `fg_ones`：零输入 symbolic const 与多 program 尾块

配置：`N=2051, BLOCK_SIZE=1024, grid=3`，覆盖两个完整块和 3 元素尾块；J 无
输入，唯一输出由现有 `const(value=1.0, shape=[N])` 产生。

v1 Lift 一次成功，但错误选择 native `bind_program_domain`。三个 normal replay
均可编译并稳定停在 `0.5583333333`；diff 的核心是 source 的 FlagGems
`tle.program_id` helper 实际返回 i64，因而多三条 `arith.extsi`。本轮没有新增
规则卡，也没有用规范化吞掉差异，而是在 Lift prompt 中把“源码明确导入
`flag_gems.utils.triton_lang_extension as tle`”作为可审计前提，要求为
`tle.program_id` 选择已有 `bind_wide_program_domain`。

v2 Lift 经一次 shape-symbol repair 后正确选卡，normal 首候选 `1.0`。masked
replay 猜成常量 0 而不是 1，语义常量不同、硬项未全过，但结构 score 仍为
`0.925 > 0.5`，所以正式状态是 `LEAKAGE_REJECTED`。

该 case 还暴露 production Lower2C 的真实缺口：`run_on_cpu` 第二次 shape inference
没有传入 `dims`，导致 symbolic const shape `[N]` 报 `KeyError: N`。修复后支持
零输入、symbolic-shape f32 const，离线 Gate2 三对最大误差均为 `0.0`。

## 9. `fg_sum`：选择 final stage，避免把 partial grid 塞入 Layer A

原 manifest 指向 `sum_kernel_1`，但 stage-1 输出长度由
`ceil_div(M, BLOCK_SIZE)` 决定，是 Layer-C 分块产生的 partial buffer。直接把它
当 whole-tensor reduce 会让 J 输出 shape 依赖 schedule。因此 ready contract
改为同一真实源码中的 `sum_kernel_2`：输入 `mid[1003]`、输出 rank 0、
`BLOCK_MID=1024`，它本身就是完整 final reduction。

Lift 一次成功；normal replay 首候选 `1.0`，masked replay 也为 `1.0`，正式
`LEAKAGE_REJECTED`。该例没有新增卡，直接复用 index tile、masked access、
flattened reduce 与 output mapping。

离线 Gate2：

| 比较 | 结果 | max abs error |
|---|---:|---:|
| source ↔ replay | PASS | `0.0` |
| source ↔ lowering | PASS | `4.76837158203125e-7` |
| replay ↔ lowering | PASS | `4.76837158203125e-7` |

## 10. `fg_mean`：`sum(partials) / M` 与真实整数 scalar cast

同样选择 final `mean_kernel_2`，并故意设置 `MID_SIZE=37`、原始总元素数
`M=1003`。该 Kernel 的语义不是 `mean(mid)`，而是：

```text
mid_sum = reduce_sum(mid[0:MID_SIZE])
M_f32 = cast(M, f32)
out = mid_sum / M_f32
```

Lift 在一次 plan 引用 repair 后正确生成上述 J，normal `1.0`、masked `1.0`，
正式仍为 `LEAKAGE_REJECTED`。首次离线 Gate2 的 source/replay 均执行成功，但
Lower2C `EXECUTION_FAILED`：CPU wrapper 把所有输入常量硬编码为 f32，且 emitter
把非布尔 cast 当成 SSA alias，导致声明为 `tensor<i32>` 的 rank-0 `M` 被直接送入
f32 division。

本轮只补既有核心 `cast` 的真实 lowering 接缝：

- CPU main 按声明为 i1/i8/i16/i32/i64 的输入发射对应 typed dense constant；
- emitter 对 tracked integer/i1 ↔ f32/int cast 发射真实 `intent.cast`；
- 没有 surviving axis 的 full reduction 默认推导为 rank 0，避免把
  `sum(partials)` 错留成 `[1]`；
- 仓库 C++ `ReduceLowering` 同步实现 rank-0 full reduction：保留 leading-unit
  parallel reduction 后，把全 1 结果 collapse 为 `tensor<1xT>`、extract 唯一
  scalar，再用 `tensor.from_elements` 构造 rank-0 tensor；重新构建
  `intent-opt` 并通过 `lower-reduce.mlir`，不再依赖旧 build 产物。

严格复用同一 Lift artifact 后，v2 normal/masked 仍为 `1.0`，离线 Gate2 PASS：

| 比较 | 结果 | max abs error |
|---|---:|---:|
| source ↔ replay | PASS | `0.0` |
| source ↔ lowering | PASS | `3.6088749766349792e-9` |
| replay ↔ lowering | PASS | `3.6088749766349792e-9` |

`fg_arange/fg_trace/fg_eye` 本轮保持 queued：当前 production Lower2C 分别缺少
iota lowering、gather lowering，以及合法构造二维对角 predicate 所需的现有
shape realization；这些接缝没有被批处理擅自补成新 op。

## 11. `fg_max`：block−1、`-inf` fill 与精确 Lower2C 读回

选择 whole-tensor final stage `max_kernel_2`，配置 `mid_size=63`、
`BLOCK_MID=64`、rank-0 输出和三维 unit grid。该 specialization 专门覆盖
`BLOCK−1` masked reduction，不把 stage-1 partial buffer 当作 Layer A 输出。

Lift 一次成功，normal replay 首候选 `1.0`；masked score 为 `0.507692`，仅略高于
方案固定阈值，因此正式状态仍是 `LEAKAGE_REJECTED`。首次离线 Gate2 报
`LOWERING_DIVERGED`，但 source 与 replay 完全一致，lowering 只差
`2.288818359375e-5`。复核实际值发现 production lowering 产生的 f32 位值正确，
差异来自 RunnerUtils `printMemrefF32` 的有限十进制打印：`91.181175` 被文本读回为
`91.1812`。

CPU runner 没有放宽 max/min 的零容差，而是在 lowering 后用受 bufferization
支持的逐元素 `arith.bitcast f32→i32` 打印位模式，再按 IEEE-754 原位恢复。
修复后的三对最大误差均为 `0.0`，并新增 rank-0 精确位读回回归。

随后 value×seed suite 又发现第二个真实 lowering 问题：normal、uniform、
large-dynamic 均通过，但 IEEE-special 中 source/replay 返回 `+inf`，Lower2C
返回 NaN，机械归属为 `LOWERING_DIVERGED`。通用 `ReduceLowering` 错用了传播
NaN 的 `arith.maximumf/minimumf`；改为与 Triton TTIR、项目 GPU row-reduction
一致的 `arith.maxnumf/minnumf` 后，max 的 4 种值域×3 seeds 共 12 case 全部
零误差通过，min IEEE-special 也固定返回 `-inf`。

## 12. `fg_min`：可见 helper 的 `+inf` 语义不能猜成最大有限值

选择 final `min_kernel_2`，配置 `mid_size=64`、`BLOCK_MID=64`，覆盖 exact-block
归约。v1 Lift 把源码 `get_dtype_max(f32)` 提升为 `max_finite(f32)`，三个 replay
均能编译但稳定停在 `0.766667`。源码真实 TTIR 的 fill 是 `0x7F800000`，即
`+inf`；重放则是 `3.40282347E+38`。这属于 J/B 对已安装 FlagGems helper 的
语义理解错误，不是可由 comparator 吞掉的等价差异。

Lift 指令因此增加一条可审计的已安装 helper 定义：floating
`get_dtype_min/get_dtype_max` 分别对应 `-inf/+inf`，J/B 用 JSON 字符串保存，π
仍不得写 helper/API 名。v2 Lift 一次成功，normal `1.0`，masked `0.507692`，
离线 Gate2 三对最大误差均为 `0.0`。

本轮严格复用 v2 Lift artifact，再生成新的 normal/masked replay，并启用正式
`--gate2-matrix`：固定源 C `BLOCK_MID=64`，shape `{1,63,64}` × value
`{normal,uniform,large_dynamic,IEEE-special}` × seeds
`{20260715,20260716,20260717}`，共 36 个 source/replay/Lower2C case。suite 不做
平均或多数票，36/36 必须逐例 PASS；本次三对最大误差全为 `0.0`。Gate1 normal
仍为 `1.0`，masked 仍为 `0.507692`，因此该矩阵只增强 rejected-sample Gate2
对照，不改变正式 `LEAKAGE_REJECTED`。

## 13. `fg_prod`：既有 reduce op 的乘法 combiner 接缝

选择 final `prod_kernel_result`，配置 `mid_size=17`、`BLOCK_MID=32`，输入使用
`near_one(scale=0.125)` 分布，既覆盖 tail 又避免把长乘积测试退化成普遍下溢。
IntentIR 已有 `reduce(fn=prod)`，C++ Lower2C 也已有乘法 combiner；本轮没有新增
IntentIR op 或规则卡，只把 `realize_reduce` v4 补齐到已有 prod 语义：重放模块
定义受审计的 `@triton.jit` 二元乘法 helper，并交给 `tl.reduce`。

v1 J 正确，但 replay 在进入编译前被安全策略拒绝：全局名 `_prod_combine` 未被
允许。修复没有开放任意 Python global，而是只允许同一模块中也经过完整 AST

## 15. `fg_vector_l1`：runtime `ord`、`abs/pow` 与安全重放边界

## 16. `fg_embedding`：数据依赖 gather 与静态 J 边界

选择真实 `embedding_kernel`，reviewed contract 为 `indices[17]: i64`、
`weight[97,13]: f32`、`output[17,13]: f32`，`BLOCK_SIZE=16`，grid 为 17 个

```text
output = gather(weight, indices, axis=0, mode=take)
```

J/B 同时保留 `indices[pid]`、`indices[pid] * N + col` 与 `pid * N + col` 三段
真实 access expression。normal replay 一次即让 interface、op multiset、dataflow、
reduction 与 predicate-effect 五个硬分量全部 `1.0`；独立 masked-J 也为 `1.0`，
所以正式状态仍是 `LEAKAGE_REJECTED`。这次没有新增规则卡：现有 pointer/memory/
output cards 从 J/B 读取数据依赖地址即可，不把具体 embedding 拓扑塞进规则库。

首次 rejected-sample Gate2 运行中，source 和 replay GPU 腿已经执行成功，第三腿
明确失败于 production CPU Lower2C 尚未消除 `intent.gather`。本轮因此补通用
`GatherLowering`：`take` 与 `along_axis` 都 lowering 为 `linalg.generic`，region
内通过 `linalg.index`、索引 `tensor.extract`、`arith.index_cast` 和数据 tensor
的 `tensor.extract` 完成真实数据依赖寻址；新 MLIR regression 同时覆盖两种 mode。
没有退回旧 JSON interpreter。

修复后 reviewed case 三方 PASS。随后严格复用同一 Lift artifact，在固定静态 J
下运行两个 value profile：

- 随机合法索引 `positive(scale=96)` + normal 权重；
- 显式整数边界索引模式 `0,96,48,1,95,0` + uniform 权重；
- 每个 profile 使用 seeds `20260715..20260717`。

6/6 case 全部 `GATE2_PASS`，source↔replay、source↔lowering、replay↔lowering
三对最大绝对误差均为 `0.0`。Gate2 orchestration 还修正为：任一执行腿失败时，
仍保存其余成功执行腿之间可计算的 pairwise agreement，便于机械归因。

曾尝试 K=`{1,15,16,17}` 的 shape matrix，但这个 source compiler view 没有
runtime K/V/D scalar，Lift 正确生成静态 `indices[17]` J；matrix builder 对
`17 != 1` fail-fast。该尝试不是动态 shape 失败，更不能当作动态 shape 已覆盖；
它界定了当前单 reviewed specialization 的证据范围。
