## 1. 总结论

当前已经成立的是：

1. 当前 24 个 accepted J 均已进入后端工作范围；
2. 5090D、H100 已有 24/24 的 `C-Fixed / Schedule-Only / Full / Source` 完整结果；
3. 5090D 上 23/24 的 Full 不慢于 Source；H100 为 22/24。新增 Gather2D 是两卡共同保留的小型负例；
4. 阶段二新增 8 项已经在 5090D、H100、RVV 单线程全部完成；
5. Stage 3 两项已在 RVV 单线程完成；阶段一 Fresh-14 仍未形成 14 项统一正式矩阵，因此不能声称 RVV 已有
   24/24 完整性能表；
6. 旧阶段二 `G_full=52.201×/89.373×` 已废弃：它把 generic fallback 到完整 J consumer 错算成 Full；
   强 canonical 重跑后的阶段二 `G_full=1.011×/1.080×`。

把三个阶段的 GPU 几何均值按 kernel 数合并，可得到以下总览。这里的“24 项合并”只用于看全局状态，
不能替代逐项结果：

最稳妥的总判断是：

- 外部竞争力：24 项 Full 相对 Source 的几何均值约为 `1.291×/1.409×`；
- C 解冻：全 24 项 `G_schedule` 约为 `1.266×/1.366×`；阶段二修正后，read-once/paired 等完整 J consumer
  已属于 canonical spine，因此这里也包含“强 canonical lowering 上的 target retile”；
- Full：全 24 项 `G_full` 约为 `1.055×/1.138×`；Stage 3 RowMask 在 5090D/H100 分别为 `1.228×/1.098×`，
  Gather2D 则因固定输出只有 256 个元素而保留约 `1.01×`；
- RVV：阶段二 8 项的 `G_schedule=1.769×、G_full=1.792×`，Stage 3 两项也已完成；但阶段一矩阵不完整，
  不能计算 24 项总值。

## 2. 旧 `52.201×/89.373×` 为什么废弃

旧数据的最终 Full latency 基本真实，但内部归因边界错误：read-once row lowering 与 paired rotation 是完整消费 J
所需的 production lowering，却只放在 Full；C-Fixed/Schedule-Only 被迫停在 generic materialized fallback。

强 canonical 重跑把这部分基础能力放回前两柱：

| Target | 旧 `G_schedule` | 新 `G_schedule` | 旧 `G_full` | 新 `G_full` | 新 Source/Full |
|---|---:|---:|---:|---:|---:|
| 5090D | 1.064× | 1.460× | 52.201× | 1.011× | 1.382× |
| H100 | 1.065× | 1.658× | 89.373× | 1.080× | 1.495× |

JSD 最直观：

```text
旧 5090D:
  Schedule-Only generic materialized = 149550.278 us
  Full read-once                    =    181.088 us

新 5090D:
  Schedule-Only read-once           =    181.696 us
  Full                              =    181.408 us
  G_full                            =      1.002x
```

因此旧 `825.843×` 衡量的是“弱 generic fallback 到完整 J consumer”；新 `1.002×` 才衡量完整消费 J 后 Full
额外增加的状态。旧 `52.201×/89.373×` 不再计入任何汇总或论文结论。

新的 Full 归因可以逐项说清：

- 5090D：JSD rank-0 capture `1.002×`；GroupNorm multi-accumulator/reciprocal/capture `1.020×`；Flash Linear
  `mma.sync` `1.072×`；其余为 1.000×；
- H100：JSD FMA `1.054×`；GroupNorm subgroup/capture `1.014×`；Flash Linear `mma.sync` `1.731×`；
  xFormers RMSNorm multi-accumulator 只有 `1.0004×`，其余为 1.000×。

## 4. 24 个 Kernel 当前真正消费了什么

| 结构类别 | Kernel | 当前 GPU 状态 | 当前 RVV 状态 |
|---|---|---|---|
| 单遍 elementwise | SwiGLU、GeGLU、DYT、TVD | vectorized/fused 单遍；多数 Full 接近 1 | TVD 已形成 producer-consumer fused scalable-vector；阶段一三项未形成正式全表 |
| normalization / statistics | RMSNorm、Fused Add RMSNorm、LayerNorm、PolyNorm、xFormers RMSNorm、xFormers RMSNorm-add、Flash one-pass LayerNorm、GroupNorm | read-once row reduction、joint/multi-accumulator 或 grouped statistics | 已有 scalable-vector、explicit reduction、joint statistics、raw moment；不同 kernel 完成度不同 |
| stable / multi-input reduction | Softmax、KLDiv、JSD、CrossEntropy | stable/read-once、gather/effect 与多输出路径 | JSD 已融合；CrossEntropy 仍为 materialized fixed-vector；阶段一 Softmax/KLDiv 正式矩阵未闭合 |
| prefix / scan | Sparsemax | prefix/frontier/tau 路径已形成强结果 | 尚无专用 prefix/segmented-scan lowering |
| padded reduction | Flash backward preprocess | subgroup-feature 与多行 live accumulator | padded/masked packet 尚未形成 Fresh-14 正式结果 |
| N-D indexed rotation | Liger RoPE、Qwen2VL MRoPE | paired rotation、双输出、消除 split/concat/gather materialization | 仍为 materialized fixed-vector，是明确缺口 |
| contraction | Flash Linear | canonical tiled contraction；Full 可进入真实 `mma.sync` | 正确 generic scalable-vector contraction；尚无专用 K blocking/高性能 contraction path |
| weighted merge | SplitK reduce | 单 CTA/多 warp 与跨 CTA D partition | producer 不在 J boundary 时保守保留，Fresh-14 正式矩阵未闭合 |
| 两级 indexed gather | Gather2D | canonical 逐级 shared-row materialization；Full 复合 runtime index map、删除中间行与 barrier | 通用 Linalg 间接 load；parallel retile 有效，尚无 vector-gather/composed-index state |
| typed row broadcast | RowMask Where2D | canonical 严格 cast+mul；Full 搜索 uniform-row zero-fill、packet width 与 grid stride | materialized fixed-vector 胜出；zero-fill/显式 vector object 已真实搜索但因分支成本被淘汰 |

这里的“消费”指 accepted J 被 materialize 为 typed Intent MLIR，C++ pass 按 op、shape、dtype、domain、
reduction/index/dataflow 匹配并生成目标代码。Python 只负责状态枚举、Q/D、编译编排与计时，不发射 CUDA/RVV
kernel。后端 matcher 不读取 kernel 名或 Source 路径。

## 6. Workload 与证据边界

所有当前正式 GPU 数据采用 code-warm/data-cold：代码已编译和加载，数据在每个样本前做 L2 eviction，计时区间
只包含 prepared launch，CUDA event 计时。RVV 固定 CPU affinity、单线程、code-warm/data-cold。

阶段二 8 项的 natural/model-level shape 与 dtype 已完整记录在：


阶段一最终汇报包含 14 项 GPU 完整性能表，但仓库内的最终汇报没有逐项汇总全部 headline shape/dtype；已有明确
记录包括 Flash preprocess `[4,16,8192,128]`、Softmax/Sparsemax `[2048,4096]`、SplitK

这是结果可读性缺口，不推翻现有 GPU timing；但在形成最终论文图前，应从当时可执行 workload report 补回精确
shape、dtype 和 observable boundary，而不是拿 closure valuation 代替 natural workload。

## 7. 目前可以写出的结论

可以写：

- 24 个 accepted J 已在 5090D/H100 被同一 production backend 真实消费；
- C 作为 non-binding prior，解冻后在全 24 项带来约 `1.27×/1.37×` 的 target retile 几何均值；
- Full 在多项 kernel 中打开固定 schedule 到不了的 materialization、traversal、reduction/index graph 与 MMA 路径；
- 最终 Full 在两张 GPU 上相对 Source 的 24 项几何均值约为 `1.29×/1.41×`；
- 同一个 J 在 GPU 与 RVV 上选择了不同 concrete MLIR 路径，跨目标复用已经有直接实例。

不能写：

- “Full 带来 52×/89×”；
- “RVV 已有 24 项完整正式矩阵”；
- “所有 24 项都从 Full 得到大幅收益”；
- “所有阶段二巨大 Full 收益都是算法创新”；
- “仅凭 requested flag 就证明某个路径已被消费”。

## 8. 当前最重要的后端缺口

1. **增强 GPU Full 的真实额外空间**：强 canonical 重跑后，阶段二只有 H100 Flash Linear 达到 1.50×；下一步
   必须寻找完整消费 J 之上的通用规约/stage/sync/index-state收益，不能再退回弱 generic baseline；
2. **补 RVV N-D indexed/in-place fusion**：Liger RoPE 与 Qwen2VL MRoPE 当前仍明显慢于 Native；
3. **补 RVV contraction**：Flash Linear 已正确执行自然 `1024×1024×8192`，但没有专用 K blocking 或高性能
   contraction lowering；
4. **补 RVV CrossEntropy gather/effect fusion**：当前 Full 与 Schedule-Only 相同；
5. **补 RVV indexed gather**：Stage 3 Gather 已正确执行并从 retile 获益，但缺少 composed index/vector gather；
6. **完成 RVV Fresh-14 正式矩阵**：这是形成真正 24 项三目标横向结论的最大实验缺口；
7. **统一补回阶段一 workload 元数据**：只补论文可复核所需的 shape/dtype/output boundary，不做无关冻结材料。
