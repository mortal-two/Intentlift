# 已通过 24 个 J：后端与论文证据总览

日期：2026-08-02

## 1. 正式集合

当前正式后端集合是 **24 个 Triton 来源、SCRC 已接受的 J**：阶段一 14 项、阶段二 8 项，加上最新的
Llama4 RoPE 与 FlashAttention forward。曾混入的 TileLang Gather2D 与 RowMask Where2D 已从正式 registry、
专用 Source adapter、baseline、结果和 aggregate 中删除。

这项修正不删除通用 gather、indexed-load、row-mask 与 zero-fill compiler pass；它只删除两个不属于当前 28-kernel
Triton 闭合集合的前端样本及其实验数字。

完整清单与 Source 证据位置见 `doc/J来源.md`。

## 2. 论文实验口径

GPU 外部比较：

```text
Source / Full
```

内部归因在 5090D、H100、RVV 上统一为：

```text
C-Fixed:
  canonical lowering path + C 的机械 target schedule 投影；一个候选，无搜索

Schedule-Only:
  与 C-Fixed 相同的 lowering path；只搜索 tile/vector/threads/warps/stages

Full:
  J 不变；额外搜索结构或数值 lowering paths；每条 path 独立搜索 schedule
```

主指标：

```text
G_schedule = latency(C-Fixed) / latency(Schedule-Only)
G_full     = latency(Schedule-Only) / latency(Full)
```

`G_schedule` 回答 C 为什么必须 non-binding；`G_full` 回答 J 是否打开普通 schedule tuning 到不了的 MLIR
实现空间。fusion、materialization、reduction tree、FMA、approximation 等只是 Full 内部 transformation，不另立
主柱。GPU Source 使用被 Lift 的原 Triton kernel；RVV 没有通用可执行 Source，因此使用严格匹配的 LLVM-RVV C、
Triton-CPU/RVV 与适用的 Expert/ggml 子集。

主性能数字使用 code-warm、L2/data-controlled 的 prepared execution；编译、module load、allocation 与 eviction 不在
计时区间。5090D 与 H100 独立搜索，不能搬运 winner。

### 3.1 FlashAttention forward 的新 H100 路径

正式 workload 为 `B=8, H=32, Sq=Sk=1024, D=64`，Q/K/V/Out 为 FP16，LSE/TMP 为 FP32；两张 GPU 都使用
cold-data、L2 flush 在计时区间外的同一 runner。新路径不是 Python kernel，也不是按名字调用 Triton：

1. certified J 的 QK/online-softmax/PV 图先由 C++ pass lower 成真实 GPU/LLVM/NVVM MLIR；
2. QK 使用 `nvvm.wgmma.mma_async`，直接从每线程 accumulator struct 提取 score，取消 score shared store/reload；
3. P 由寄存器 score 形成并只 stage 一次，PV 改用 `nvvm.wgmma.mma_async`，加权输出 accumulator 跨 key tile 常驻寄存器；
4. K/V 用 16-byte `nvgpu.device_async_copy` 从 global stage 到 shared，避免通用 load/store 的中间寄存器流量；
5. 每个候选仍先和 Source reference 比较 Out、LSE、TMP，正确后才进入计时。

H100 三轮搜索结果：

| C-Fixed | Schedule-Only | Full | `G_schedule` | `G_full` | Source |
|---:|---:|---:|---:|---:|---:|
| 1093.024 us | 1044.128 us | 364.768 us | 1.047× | 2.862× | 425.312 us |

Full winner 的最大绝对误差为 Out `1.526e-5`、LSE `1.431e-6`、TMP `4.768e-7`；cubin 为
`31,208 bytes`。七个交替配对确认批次中，Full 为 `466.048--468.896 us`，Source 为
`420.640--446.496 us`，中位数分别为 `466.432/425.312 us`。因此论文应同时报告搜索三柱的
`2.862×`、搜索中的 `1.166×` Source 加速和配对确认的 9.7% Source gap，不能用一次较快样本冒充绝对 winner。
独立重复运行仍选中同一路径，配对中位数为 `418.752/383.136 us`（Full/Source=`1.093×`），相对差距与主运行一致。

5090D 不开放 Hopper path；同一 workload 的七批确认结果为 Full `522.016 us`、Source `520.160 us`
（Full/Source=`1.004×`），即保持 Source parity。其三柱为 `649.024 → 612.992 → 522.944 us`。
可直接画表的紧凑结果见 `doc/results/flash-forward-20260802/summary.csv`。

## 4. Full 真正增加了什么

当前已经由真实 MLIR/C++ pass 形成并被搜索的主要状态包括：

- producer/reduction/epilogue fusion 与中间 materialization elimination；
- sequential/subgroup/workgroup/multi-stage reduction topology；
- multiple-reduction joint accumulation；
- prefix/frontier/scan-shaped Sparsemax path；
- FP32 FMA 与执行域 Q/D 过滤的 approximate state；
- contraction 的 tiled path 与 GPU `mma.sync`；
- RoPE 的 paired/interleaved rotation、双输出与 angle reuse；
- Flash forward 的 direct V fragment、shared row padding、fragment lifetime 与 B-fragment load state；
- Hopper Flash forward 的 register-consumed NVVM WGMMA QK、16-byte async K/V staging，以及可搜索的
  WGMMA-PV/compact-query/normalized-carry/BM128 warpgroup 状态；
- RVV 的 dynamic-VL vector reduction、multi-output sibling fusion、widening FP16→FP32 reduction。

这些 transformation 以 A/IR pattern、B hard boundary、current MLIR state 与 target capability 匹配；Python 只枚举、
执行 Q/D 与计时，不发射计算 kernel。系统没有 `family_id` 或按 kernel 名选择 recipe。

## 5. C-prior 的独立作用

`C` 不改变候选集合，也不改变充分预算下的最优可达性能；它只排列同一 concrete candidate universe。当前已在
四个 candidate universe 未变化的 kernel 上用完整 latency map 重算 `B=32` 的搜索前缀：

| Kernel | 5090 `Erase-C/C @ B=32` | 5090 到 95% 最优：C / Erase-C | H100 `Erase-C/C @ B=32` | H100 到 95% 最优：C / Erase-C |
|---|---:|---:|---:|---:|
| Llama4 RoPE | 1.000× | 3 / 9 | 1.000× | 3 / 15 |
| TVD | 1.004× | 7 / 7 | 1.002× | 4 / 7 |
| xFormers RMSNorm | 1.003× | 1 / 9 | 1.000× | 3 / 12 |
| Sparsemax | 1.033× | 222 / 221 | 1.056× | 236 / 222 |

表中固定预算比值严格定义为 `latency(best Erase-C@B) / latency(best C@B)`，大于 1 才表示 C 在固定预算下更好。
四项当前仍使用同一 candidate universe 的固定预算质量几何平均为 `1.010×/1.014×`。Sparsemax 在 `B=32`
时受益 `1.033×/1.056×`，但到 95% 最优的全程排序反而略差；这些负例说明 C 是不保证必胜的启发式先验，
而不是隐藏的合法性或性能权限。FlashAttention forward 新增了 WGMMA/async 路径，旧五项表中它的 C-prior
数字已不再属于当前 candidate universe，必须重跑后再并入 aggregate，不能沿用。其余逐项微秒数与完整候选
规模见 `doc/results/c-prior-20260802/gpu-five-kernel-b32.csv`。

## 6. RVV 的准确状态

原有 RVV formal 子集为七项：TVD、Softmax、xFormers RMSNorm、Flash backward preprocess、Llama4
RoPE、Fused Add RMSNorm 与 Flash one-pass LayerNorm，`G_schedule/G_full` 几何平均为
`1.824×/4.636×`。本轮又在统一 `symbolic-medium-v1`、单线程、cold-data、VLEN128 口径下增加
SwiGLU、Liger RMSNorm、GeGLU、LayerNorm、DYT、Sparsemax、KLDiv、PolyNorm 八项；新八项几何平均为
`1.126×/1.577×`，其中 LayerNorm `G_full=5.356×`、PolyNorm `2.207×`、Sparsemax `1.679×`，
DYT `1.008×` 是明确负例。

本轮随后又补齐 xFormers RMSNorm-add、SplitK reduce、JSD、CrossEntropy、GroupNorm、Liger RoPE、
Qwen2VL MRoPE 与 Flash Linear。medium 四项 `G_schedule/G_full=1.150×/1.055×`，natural 四项为
`1.732×/1.184×`；GroupNorm 的 `5.507×` retile 与 `1.963×` Full 是最强正例，而两类 RoPE 与
Flash Linear 的 `G_full≈1` 是明确负例。

因此目前 **23/24** 项已有 RVV 三柱数据。原七项、medium 八项、remaining medium/natural 两组的 workload
配置不同，不能把 23 项直接混算一个 aggregate。唯一缺口 FlashAttention forward 因 RVV ContractView 尚不能
消费 `logical_update_relation` 而 fail closed。LLVM-RVV C 覆盖 23/24；Triton-CPU/RVV 有 8 项 correctness、
7 项统一 formal latency；Expert 与 ggml 只覆盖严格适用子集。新增明细见
`doc/results/rvv-core8-medium-20260802/summary.csv` 与 `doc/results/rvv-remaining8-20260802/summary.csv`。

新结果也保留负例：启用完整 `rv64gcv_zfh_zvfh` 的 LLVM-RVV C 在 Flash one-pass LayerNorm 上约快于 Full
`4.88×`。旧四项 LLVM-RVV C 需要用同一 flags 重新配对，因此当前不报告混合 flags 的七项外部 aggregate。

这已经接近完整横向覆盖，但仍不足以计算统一口径的 24-J RVV aggregate。详细结果与外部 baseline 见
`doc/RVV可迁移性与外部基线实施报告_2026-08-01.md`。

## 7. 对论文主张的裁决

当前可以成立：

1. **J 被真实消费**：24 个 J 都进入同一 `J -> Intent MLIR -> target executable` 后端；不是 Python emitter。
2. **C 解耦有效**：同一 canonical path 解冻 schedule，在两张 GPU 上有约 1.26×/1.34× 几何平均收益。
3. **J 打开额外实现空间**：Full 在多个结构类上找到 Schedule-Only 不可达的 concrete MLIR state；H100
   Flash forward 的 register-WGMMA/async path 给出 2.862× 的强正例，同时仍保留大量 `G_full≈1` 负例。
4. **跨目标复用存在**：同一个 J 在 CUDA 与 RVV 上选择不同 lowering/schedule state，已有可执行实例。
5. **外部竞争力总体成立**：GPU 全 24 项相对 Source 的几何平均约为 1.31×/1.44×；5090D Flash forward
   达到 parity，H100 的 S=1024 严格确认仍约慢 1.097×，跨 shape 为慢 1.05--1.12×，均如实保留。

当前不能成立：

1. **跨前端实证**：删除两个 TileLang 输入后，正式 24 项全部来自 Triton。这组实验不能证明 Triton/TileLang/CUDA
   多前端统一；该表述只能作为接口设计，或等待独立认证的非 Triton case study。
2. **24-J 三目标完整矩阵**：RVV 已有 23 项三柱；Flash forward 因缺失的 B consumer 明确 N/A，且现有四批配置尚未统一。
3. **Full 普遍大幅加速**：全量 `G_full` 是 1.054×/1.191×；创新点是打开可搜索的具体状态，不是保证每项 1.5×。
4. **所有 target 均达到 Source**：H100 Flash forward 在七批配对确认中仍慢约 9.7%，Qwen2VL MRoPE 也是清楚负例。

## 8. 论文前还必须补的内容

按重要性排序：

1. **补完整 workload 表**：每个 kernel 的 headline shape、dtype、layout、observable outputs 与 cache/timed boundary；
   这是 reviewer 判断公平比较的必要信息，不是内部冻结材料。
2. **收口 RVV 正式矩阵**：23 项已有三柱，下一步统一可合并的 workload/flags；Flash forward 保留明确 N/A，
   直到 `logical_update_relation` 有真实 RVV consumer。
3. **扩展 C-prior 覆盖**：当前四项小表已建立相同 universe、相同预算的口径；继续覆盖更多 reduction、fusion 与
   contraction kernel，确认候选数收益是否稳定。
4. **补机制解释**：GPU/RVV 各选 2--3 个真正赢的 state，用 post-pass MLIR、traffic/sync/register/shared-memory 或
   RVV instruction 解释收益；不再制造额外主柱。
5. **收口 H100 Flash forward**：跨 shape 已完成；单缓冲 async-K/V + register-WGMMA 的三柱增益为
   `2.42--3.33×`，但严格确认仍慢 1.05--1.12×。BM128 shared-score 路径已证明不合适，下一步只考虑
   register-resident BM128、双缓冲或同步收缩。
6. **决定跨前端主张**：若论文必须实证多前端，后续单列一个正式认证的非 Triton J case study；否则删掉实验性
   “跨前端性能”措辞，只保留 Source-realization-independent 的系统设计。

完成前四项后，后端论文逻辑是完整且可审查的；当前已具备核心系统、GPU 主结果与 23/24 RVV 横向覆盖，
剩余工作主要是 RVV 统一口径 aggregate、C-prior 扩面和 workload 元数据收口。
