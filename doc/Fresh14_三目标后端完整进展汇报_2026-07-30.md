# Fresh-14 三目标后端完整进展汇报

日期：2026-07-30  
主目标：真实消费 14 个闭合 J，完善 5090D、H100 与 RVV 的 C++/MLIR 后端，并形成可归因的
`C-Fixed / Schedule-Only / Full / Source-or-Native` 实验。当前实现优先级以 5090D/H100 为主，但既有
RVV 能力和结果属于总后端结论的一部分。

## 1. 结论

GPU 方面，14 个 kernel 已全部进入同一 CUDA 后端、搜索器和冷数据测量协议，并在 5090D/H100 上得到
完整四柱结果。IntentIR winner 在当前 GPU 表中全部不慢于 Source，Fresh-14 的 Source/target 几何均值为：

- 5090D：`1.261x`；
- H100：`1.373x`。

RVV 方面，已经完成通用 dynamic-VL schedule、producer/reduction fusion、显式 vector reduction、共同根
joint statistics 和 raw-moment variance 等真实 C++/MLIR 能力。两个自然负载已完成多批稳定确认：

- PolyNorm：`G_full=28.668x`，Full 比独立 Native RVV 快 `2.069x`；
- LayerNorm：`G_full=11.258x`，Full 比独立 Native RVV 快 `2.778x`。

此外，Fused Add RMSNorm `5.317x`、Flash one-pass LayerNorm `3.354x` 已在工程筛选中出现，但尚未达到上述
多批正式结果的证据等级，因此不计入正式强 cell。

内部消融的全局状态是：

- Schedule-Only 已经证明 C 解冻后的跨目标重调优有价值：全表几何均值为 `1.168x/1.197x`；
- Full 已经在 Sparsemax 与 Flash backward preprocess 上证明真实结构空间存在；
- Full 全表几何均值为 `1.073x/1.185x`，只统计结构实际适用的 Flash+Sparsemax 时为
  `1.548x/2.849x`；
- GPU 当前达到 `G_full >= 1.50x` 的 cell 为 3 个：5090D Flash、H100 Flash、H100 Sparsemax；
- 加上正式 RVV PolyNorm 与 LayerNorm，三目标当前共有 5 个正式 `>=1.50x` cell、4 个 kernel，并覆盖
  multirow live accumulator、prefix/frontier、joint statistics、raw moment 等至少 4 条结构机制；
- 因此“4 个 kernel、3 条机制、3 个 target”已经成立，但“至少 6 个正式强 cell”还差 1 个；
- GPU Fresh-14 全表已经完整，RVV Fresh-14 的统一正式全表尚未完成，不能计算 RVV 全表几何均值。

换句话说，后端已经从“能够运行 J”推进到“同一个 J 在 GPU 和 RVV 上打开不同的真实结构搜索空间”。
GPU 的强收益集中在 scan/padded reduction；RVV 的强收益集中在删除 Linalg materialization、共同根多统计
和 scalable-vector reduction。仍不能声称 Fresh-14 大多数 kernel 都从 Full 获得大幅增益，也不能用筛选
数据代替缺失的 RVV 全量正式矩阵。

## 2. 实验定义

四个比较对象固定如下：

```text
External baseline:
  GPU 使用原始 Triton Source kernel；RVV 使用独立 Native RVV 实现。
  两者只用于绝对竞争力比较，不替代内部消融。

C-Fixed:
  DirectLower(J) + C 的一次确定性 target schedule 投影；不搜索。

Schedule-Only:
  与 C-Fixed 相同的目标程序结构；只开放 threads、tile、vector、warps 等 schedule。

Full:
  完整包含 Schedule-Only；额外开放由 typed J、B hard facts、target capability、
  pass precondition 及必要时 Q/D 共同准入的结构/数值执行状态；每个状态独立调 schedule。
```

内部指标是：

```text
G_schedule = latency(C-Fixed) / latency(Schedule-Only)
G_full     = latency(Schedule-Only) / latency(Full)
```

当前 CUDA 正式协议为 `natural-headline-v1`、code-warm/data-cold、CUDA event。三柱 winner 在同一候选空间中
测量；最终 Source/target 使用交替批次，避免时钟漂移。这里的 cold 指数据在每个计时样本前做 L2 eviction，
不是把编译或首次加载开销混入 kernel latency。

RVV 正式协议使用 riscv64、VLEN=128、固定 CPU affinity、单线程、code-warm/data-cold。Native baseline 是
独立 case-authored C/RVV intrinsic 实现，以 `-O3 -march=rv64gcv_zfh -fno-fast-math -ffp-contract=off` 单独编译；
它不读取 IntentIR MLIR、搜索状态、winner 或目标 object。PolyNorm/LayerNorm 的稳定确认使用
`warmup=3、cold-iterations=3、batches=3`，122 个实际 executable 全部通过 correctness。

## 4. 14 个 J 是否被真实消费

CUDA 侧 14/14 已完成正式消费与横向测量；RVV 侧已经建立同一 14 项 suite、独立 Native baseline 与统一
controller，并对多个正式 J 完成真实 lowering/搜索，但全量正式测量尚未闭合。这里的“消费”不是把 J 名称
映射到 Python kernel，而是：

1. accepted J 被 materialize 为 typed Intent MLIR；
2. C++ pass 根据 op、shape、dtype、domain、reduction/scan/dataflow 结构做 matcher；
3. matcher 不读取 kernel 名、Source 路径或历史 winner；
4. CUDA 生成真实 `gpu.launch`，经 LLVM/NVVM 生成 cubin；RVV 经 Linalg fusion/vectorization、LLVM 与
   `llc` 生成 riscv64 `+v,+zfh` object；
5. Python 只枚举状态、编译、执行 Q/D 和计时，不发射目标 kernel；
6. 只有编译后 MLIR 中实际记录的 topology、trace 和 launch state 才计入 Full。

14 项当前分别落入如下结构类别：

| 类别 | Kernel | CUDA / RVV 当前状态 |
|---|---|---|
| 单遍 elementwise | SwiGLU、GeGLU、DYT | CUDA 已融合；RVV 主要是 scalable schedule/producer fusion，作为物理负例 |
| normalization | RMSNorm、Fused Add RMSNorm、LayerNorm、PolyNorm、Flash one-pass LayerNorm、xFormers RMSNorm-add | CUDA read-once；RVV 已有显式 vector reduction、joint statistics、raw moment，并在 PolyNorm/LayerNorm 形成强证据 |
| stable reduction | Softmax | CUDA 已保留 input/exp live state；RVV 已有 fused stable Softmax pass，但完整 online/resident state 与正式强结果未闭合 |
| prefix/scan | Sparsemax | CUDA prefix/frontier/tau 已形成强证据；RVV 尚无专用 prefix/segmented-scan lowering |
| multi-input reduction | KLDiv | 正式 J 是逐行 `exp -> sub -> mul -> sum(axis=1)`；CUDA read-once，RVV multi-input/mixed-dtype packet 能力仍待统一 |
| padded reduction | Flash backward preprocess | CUDA 多行 interleaved live accumulator 已形成强证据；RVV padded/masked packet path 尚未横向闭合 |
| weighted merge | SplitK reduce | CUDA 已有单 CTA/多 warp 与跨 CTA D partition；RVV producer 不在 J boundary 时保留为负例 |

## 5. 已经成立的主要能力

### 5.1 C 解冻后的 target retile

xFormers RMSNorm-add 的 `G_schedule=4.402x/5.259x` 是当前最清楚的跨 target 重调度证据。它说明 C 不能作为
目标无关的固定发射参数：同一 direct lowering 在新 GPU 上解冻 threads/tile/vector 后，能够消除严重失配。

这属于 Schedule-Only，不冒充 Full。它回答的是“同一个结构为什么需要跨目标重调优”。

### 5.2 Sparsemax prefix/frontier/epilogue live state

Full 识别 typed `scan -> support -> (rank,sum) -> tau -> epilogue` 图，并搜索：

- prefix packet width；
- epilogue X packet 预取与 SSA 保留；
- frontier ballot 直接选出最后 supported `(rank,sum)`；
- leader-only tau 与广播；
- 单行/多行 warp mapping。

结果为 `G_full=1.489x/1.503x`。5090D 与 H100 从同一候选并集选择不同 executable，说明 J 被用于构造
目标相关的 concrete MLIR 状态，而不是携带一个固定 GPU recipe。

### 5.3 Flash preprocess 多行 live accumulator

Full 为 typed padded reduction 构造 2/4/8 行交错的 subgroup-feature 状态：同一 subgroup 内多个行 accumulator
同时存活，feature load/multiply/add 交错发射，之后逐行完成 shuffle/store。Schedule-Only 保留 serial-row
direct-lowering spine。

结果为：

- 5090D：`G_full=1.609x`；
- H100：`G_full=5.399x`。

两卡 winner 不同：5090D 选择更宽的单行映射，H100 选择四行交错。这是目前最强的“同一 J 打开不同目标
执行图”的证据。

### 5.4 RVV target retile 与显式 scalable-vector reduction

RVV search 已实现 fixed/scalable parallel tile、reduction tile 与 joint tile 的独立候选；scalable state 使用
`vector.vscale`/dynamic VL，而不是把 GPU block size 翻译成一个固定 RVV 宽度。Full 可在精确 pass contract 下
组合 producer fusion、reassociation、显式 vector reduction 与 joint reduction。

C++ matcher 面向 pure-tensor Linalg row reduction：要求 parallel dimensions 加最后一维 reduction、可验证 identity、
f32 add/max combiner及 lane-wise producer payload。显式 vector reduction 需要 reassociation；joint reduction 还要求
producer fusion 与多个 reduction 共享 domain/root。请求未命中时 pass fail closed，不能只靠 Python 标签声称命中。

这条能力解释了为什么 RVV 的 Full/Schedule 差距可能远大于 GPU：Schedule-Only 仍在 materialized 固定结构里
调 VL/tile，而 Full 能删除完整 tensor traversal，并把 scalar/Linalg reduction 改成真正的 `vfred*` 执行图。

### 5.5 RVV joint statistics

joint state 从多个相同 row domain、相同 axis 的 reduction 沿 identity-mapped elementwise DAG 回溯共同 root，
生成一个 dynamic-VL loop、一次 root `vector.transfer_read` 和多个 vector accumulator；每个 statistic 只在行末
做一次 horizontal finalize。不同 root、ordered reduction、非零 init、非 identity producer 或 dominance 不成立时
均 fail closed。

PolyNorm 的 `28.668x` 不是“vector width 调得更好”，而是从多个独立 materialized reduction 变成共同 root
单遍状态；Full 相对 Native 的 `2.069x` 说明该通用图变换同时具备绝对竞争力。

### 5.6 RVV raw-moment variance

对于精确匹配的 centered-variance 图，Full 不再物化并规约 `(x-mean)^2`，而在同一 root traversal 中联合累积
`sum(x)` 与 `sum(x²)`，行末重建 variance。它改变浮点观察顺序，只作为 reassociation/QD 下的
observation-changing state。

LayerNorm 的稳定 `G_full=11.258x`、Native/Full `2.778x` 是该机制的正式证据。首轮筛选中 raw-moment 相对
最佳 non-joint Full 为 `1.813x`，说明收益不仅来自一般 fusion/vectorization。

### 5.7 RVV 已实现但尚未完成性能闭环的能力

- fused stable Softmax matcher 已能识别 row max、exp、row sum 与 divide，并记录实际删除的 materialization；
- Softmax 当前工程收益约为 1.25x 级，完整 online recurrence/resident-row 路径尚未闭合；
- RVV search 能识别 scan fact，但尚无专用 prefix/segmented-scan lowering，因此不能声称已消费 Sparsemax scan；
- multi-input、mixed-dtype、masked/padded row packet 尚未统一进入 joint vector state；
- Flash one-pass LayerNorm 已命中 joint/raw-moment，但其 joint 边际仅 1.063x，仍需多批复测和瓶颈归因。

## 6. SplitK 新能力与边界

SplitK Full 新增了 cross-CTA D partition：同一输出 row 的连续 D packet 被 grid-z 上多个 CTA 无重叠地处理；
LSE 只由 `z=0` 的 row leader 写入。该能力由 C++/MLIR pass 生成，并记录
`cross_cta_d_partition` 与 `d_partitions`；runtime-stride、非连续 D 或不兼容的 row/warp geometry 会 fail closed。

增量复测中：

- H100 选择 `d_partitions=8`：`15.616 -> 14.432 us`，`G_full=1.082x`；
- 5090D 淘汰跨 CTA 状态，保留原有单 CTA winner：`G_full=1.000x`；
- 相对 Source 仍约为 `2.93x/3.61x`。

它证明搜索会按 target 接受或拒绝真实拓扑，但当前 D=256、短 kernel 的自然负载不足以让额外 CTA 产生
1.5x 收益，所以该结果应作为能力和物理边界，而不是 headline。

## 7. 当前正在实现的下一条 Full 路径

普通 row reduction 现有每线程 feature strip 使用一条串行 accumulator 链；现有 `reduction_parts` 则是跨 block
多 stage，两者不是同一机制。当前新增的 Full-only 状态为：

```text
single chain:
  a0 = (((id + x0) + x1) + x2) + ...

2/4 live chains:
  a0 = id + x0 + x4 + ...
  a1 = id + x1 + x5 + ...
  a2 = id + x2 + x6 + ...
  a3 = id + x3 + x7 + ...
  local = tree_combine(a0, a1, a2, a3)
  block = existing warp/workgroup tree(local)
```

这条路径的目的不是增加 tile，而是缩短每线程的浮点依赖链、暴露 ILP，并改变局部 reduction tree。当前状态：

- C++ pass 已增加 `accumulator-chains={1,2,4}`；
- 只在 single-launch register row-reduction 上准入，multi-stage、multi-row 或不够长的 feature strip 会 fail closed；
- Schedule-Only 固定为 1；Full 枚举 2/4，并把它们标为 observation-changing；
- Q/D_search 决定候选能否计时，D_cert 决定 winner 能否消费；
- 编译后 MLIR 显式记录 `accumulator_chains` 和
  `cuda.reduction.per_thread_multi_accumulator_tree.v1`；
- 已通过 C++ 编译、152/152 MLIR tests、38/38 backend/search tests；
- 5090D/H100 的性能筛选尚未完成，因此本文不声明它已有性能收益。

优先测试对象是 RMSNorm、Fused Add RMSNorm、LayerNorm、PolyNorm、Flash one-pass LayerNorm 与 KLDiv。若两卡都
不选择该状态，结论应是“现有 warp 数和全局并发已足以隐藏局部链”，而不是继续堆近义开关。

## 8. 为什么多数 Full 增益仍小

### 8.1 不是 14 个 kernel 都有可删除的中间流量

SwiGLU、GeGLU、DYT 已是单遍 producer-consumer fusion；普通 Norm 已把输入保存在 register/frontier，同一趟
维护多个统计量，并在规约后直接 epilogue；Softmax 已保留输入和 exp live state。对这些状态再打开一个 fusion
flag，不会产生新的执行图。

### 8.2 read-once 不等于一定达到峰值带宽

实际 latency 还受规约依赖、shuffle/barrier、register pressure、occupancy、特殊函数吞吐和 launch 下限影响。
因此后端仍可增加规约树、同步图或 stage decomposition，但必须由 profile 指向真实瓶颈，不能因为它们是
memory-bound 就假设任何 schedule 都等价。

### 8.3 Source 很强不妨碍内部消融成立

Flash preprocess 的 Full 比 Schedule 快很多，但只比 Source 快约 1.05--1.07x，因为 Triton Source 本身已经是
高性能实现。内部 `G_full` 证明 J/search 打开了固定结构 schedule 到不了的路径；Source/target 则证明最终结果
没有以失去绝对竞争力为代价。两者回答不同问题，必须同时报告。

### 8.4 不能靠重新定义 C-Fixed 制造数字

C-Fixed 应是 DirectLower(J) 上 C 的机械投影。可以修正错误地提前放入 DirectLower 的搜索型结构，但不能任意
选择一个差 schedule，也不能修改 Source、shape、dtype 或 correctness policy。当前结果保留大量 `1.00x` 负例，
正是为了使 Full 的强结果可归因。

### 8.5 为什么同一个 J 在 RVV 上会出现几十倍，而 GPU 上多数只有几点

差别不来自对 RVV 人为使用更弱 baseline。CUDA row-reduction direct lowering 已经是 read-once register/frontier
状态，Full 很难再删除 2--3 次 HBM traversal；RVV 的 canonical Linalg 结构在 joint state 之前仍可能保留多个
producer/statistics tensor、多个 loop和多个完整 traversal。Schedule-Only 只能重调这些既有 loop 的 tile/VL，
Full 才能把它们改写成一次 root load、多个 live vector accumulator和融合 epilogue。

因此 PolyNorm 的 28.668x 与 LayerNorm 的 11.258x 正是跨目标复用故事：J 表达相同计算与合同，但不同 target 的
初始实现结构和主瓶颈不同，后端必须从 J 构造不同 transformation path；不能把一个 GPU recipe 直接移植到 RVV。

## 9. 当前缺口与下一阶段计划

当前距离目标的缺口为：

- GPU 强 cell 为 3 个；加上正式 RVV PolyNorm/LayerNorm 后，三目标强 cell 为 `5/6`；
- 正式强 kernel 已覆盖 Flash preprocess、Sparsemax、PolyNorm、LayerNorm，即 `4/4`；
- 已成立强机制至少包括 GPU multirow、GPU prefix/frontier、RVV joint statistics、RVV raw moment，超过 `3/3`；
- 5090D、H100、RVV 单线程均已有至少一个正式 `>=1.50x` cell；
- 5090D Full 全表几何均值 `1.073x`，低于 `1.15x` 目标；
- H100 Full 全表几何均值 `1.185x`，已超过 `1.15x`。
- RVV Fresh-14 全量正式表尚未完成，因此 RVV 全表几何均值与三目标完整矩阵仍是硬缺口；
- Fused Add RMSNorm/Flash one-pass LayerNorm 的 RVV 筛选结果在多批确认前不用于补足第 6 个 cell。

接下来只按高杠杆顺序推进：

1. 在 5090D/H100 上筛选 multi-accumulator reduction tree，先覆盖多个正式 J，而不是单 kernel 特化；
2. 对 winner/loser 检查实际 post-pass MLIR、register、shuffle/barrier 与 target assembly，确认收益来源；
3. 若该机制不足，继续寻找能够删除 traversal/materialization 或改变 stage/sync graph 的第三条通用 GPU 路径；
4. 完成能力后重新跑 Fresh-14 全表，而不是只报告被挑中的强项；
5. RVV 保留 joint/raw-moment 的正式成果；补齐 Fresh-14 单线程正式矩阵，并优先确认已有强筛选 cell；
6. RVV 新能力后续集中在 online Softmax、prefix/segmented scan 与 multi-input/mixed-dtype/padded packet，当前
   不与 5090D/H100 的主线实现争抢优先级。

明确不做：

- 不把单纯 tile/warps/vector 变化称为 Full；
- 不用 Python 发射目标 kernel；
- 不按 kernel 名或 benchmark 名准入；
- 不修改 Source、自然 shape、dtype 或 Q/D 来追求数字；
- 不用哈希、冻结账本或流程性材料替代后端能力和性能结果；
- 不把尚未测得的候选写成性能结论。
