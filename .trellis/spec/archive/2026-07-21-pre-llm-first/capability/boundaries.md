# 能力边界

## 四种“不能”（不要混为一谈）

| 类型 | 含义 | 性质 |
|---|---|---|
| **不能表示** | IR 没有这个构造 | **设计选择**,加构造即可解决,不是定律 |
| **不能验证 / 弱保证** | 能表示能跑,但证书很薄 | **真·认知天花板**,要诚实声明 |
| **不能可靠提取** | IR 装得下,但 LLM 从混淆源码里恢复不出 | LLM 能力 + prompt/evidence 问题 |
| **不能 lower 到某 target** | J 已明确，但 backend 未消费某个 op/B obligation | target capability gap，不得反向删改 J |

同一个 Kernel 可以同时在四个维度拥有不同状态，例如“可表示、可提取、Gate 有限通过，
但 CUDA backend 对 partial writeback 尚 unsupported”。不得压成一个 overall ready。

## 最锋利的能 / 不能界线:固定计算图 vs 数据依赖的图结构

- **数据依赖的「值」和「地址」**(gather/scatter、select/where、segment-reduce):**计算图形状固定**,只是图里流动的数值 / 索引运行时才定 → **干净可表示,动态验证兜住**。
- **数据依赖的「结构」**(循环跑几次、分支走哪边、递归多深):**每个输入改变计算图本身** → **真正的前沿**,逼出控制流决策(见 [../ir/representation-decisions.md](../ir/representation-decisions.md))。

绝大多数"数据依赖"诉求落在第一类(本就能做);真正硬的是第二类(门控纳入)。

## 诚实的天花板(规范明写)

1. **验证的地板**:源码执行一致性是**测试输入域**的保证,不是全域形式证明。这是范式固有天花板,大方承认。
2. **非纯计算**:I/O、动态内存分配、不可控全局可变状态 → 本质 out-of-scope。
3. **不可控非确定性**:带种子 / 可控的能用 tolerance 验;依赖硬件时序的真竞争 → 弱保证或排除。
4. **非张量代数算法**(排序 / 哈希 / 图 / 复杂 DP):可用 gather/scatter + loop 硬凑,但提取与验证都弱 → 标"低保证",不假装强。

## 纪律

- 任何"砍掉某覆盖范围 / 不重试 / 采样"的边界,必须显式记录被丢弃了什么,不得静默截断(静默会让人误以为"全覆盖了")。
